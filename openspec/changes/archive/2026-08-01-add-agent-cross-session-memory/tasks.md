## 4. Automatic path: extraction on compaction

- [x] 4.1 New function `extract_memories`, shaped like `summarize_turns`: reuses `wire_format.build_request_body`/`endpoint`/`apply_auth`/`translate_sse_data`, no tools declared, accumulates full text instead of streaming, operates on the same `&turns[..split_at]` slice `maybe_compact` already computes. Instruction text (`MEMORY_EXTRACTION_INSTRUCTION`) explicitly allows an empty/no-op response and asks for one fact per line, no numbering/bullets/preamble (parsing is a newline split, not a second structured-output round trip). **Implementation choice**: rather than duplicating `summarize_turns`'s ~60 lines of HTTP/SSE-accumulation logic in a new function, `summarize_turns` itself was parameterized with an `instruction: &str` argument (replacing the hardcoded `SUMMARIZATION_INSTRUCTION` reference) so `extract_memories` can call it directly with `MEMORY_EXTRACTION_INSTRUCTION` and only add the memory-specific parsing/saving on top — `extract_memories` itself is ~25 lines. Required updating 4 pre-existing `summarize_turns` call sites (1 production, 3 tests) to pass `SUMMARIZATION_INSTRUCTION` explicitly; added `#[allow(clippy::too_many_arguments)]` (now 8 params).
- [x] 4.2 Parse the extraction response into zero or more memories (one per non-empty line, trimmed) and save each via `AgentMemoryPort::save` with source `Automatic`; per-line save failures are swallowed (`let _ = memories.save(...)`), matching `execute_remember`'s own best-effort-write posture for a non-critical background enhancement.
- [x] 4.3 Call `extract_memories` from `maybe_compact` at the exact point it already fires (after confirming `should_compact` *and* after compaction's own `summarize_turns` call succeeds, using the identical pre-mutation `&turns[..split_at]` slice, before `turns` is overwritten by the compaction rewrite). **Deviation from the original wording**: extraction's failure is *not* logged, unlike compaction's own summarization failure. `summarize_turns`'s `Option<String>` return can't distinguish "call failed" from "model had nothing worth remembering" without additional machinery (e.g. a `Result<Option<String>, ()>` split), and unlike a failed compaction summarization — which has a real, visible consequence (turns stay uncompacted, risking a future context-limit failure) — a failed/empty extraction has no visible consequence at all; it's a silent, best-effort background enhancement. Logging every no-extraction case at `Warn` would be noisy and misleading for what's usually just "nothing memorable happened this turn." Both outcomes fall through `extract_memories`'s single `let Some(response) = summarize_turns(...) else { return; }` with no distinction.
- [x] 4.4 Tests: 3 direct `extract_memories`-level tests (`extract_memories_saves_one_memory_per_non_empty_line`, `_saves_nothing_when_the_response_is_empty`, `_saves_nothing_when_the_http_call_fails`, using a new `FakeMemories`-observing setup) plus 1 `maybe_compact`-level integration test (`maybe_compact_triggers_extraction_and_saves_memories_when_it_succeeds`) proving the wiring itself — that a real compacting generation triggers *two* sequential HTTP calls (summarization, then extraction) and the extracted line ends up in the memory port. The 2 pre-existing compaction-trigger tests (`maybe_compact_replaces_older_turns_and_emits_a_rich_block_notice_when_triggered`, `maybe_compact_preserves_the_system_prompt_across_a_trigger`) needed no changes beyond passing `&FakeMemories::default()` — their single-shot HTTP fixture now also receives extraction's second request, which fails fast with a connection-refused error (the fixture's listener has already served its one accepted connection and been dropped), which `extract_memories` already treats as a normal, silent no-op failure; confirmed empirically (test run), not just by inspection. New `http_fixture_sequence` test helper added alongside `http_fixture` for the 2-request integration test, rather than reshaping `http_fixture` itself (would have changed its `Vec<u8>` return type for every existing call site).
