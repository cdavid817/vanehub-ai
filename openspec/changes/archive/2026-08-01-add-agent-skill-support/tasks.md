## 2. `tooling::skills`: binding schema and repository

- [x] 2.1 Add `skill_api_agent_bindings` migration. **Design correction:** dropped the `enabled` column from the original task wording — the *Skill's own* `enabled` flag already gates every consumption path (mirroring `enabled_skills_bound_to`'s existing CLI-mount query), so a second per-binding enabled flag would be redundant; "disable for this agent" is just unbind. Also dropped SQL `FOREIGN KEY`/`ON DELETE CASCADE` clauses — the existing `skills`/`skill_agent_bindings` tables declare none either (this codebase hand-rolls cascade deletes in application code, e.g. `delete_skill`, rather than relying on SQLite FK enforcement); matched that convention instead of introducing a new one. Final shape: `(skill_id, scope, workspace_path, agent_id, created_at, updated_at)`, PK `(skill_id, scope, workspace_path, agent_id)`. `delete_skill` extended to also clean up this table (same transaction, same pattern as its existing `skill_agent_bindings` cleanup).
- [x] 2.2 New `SkillApiBindingRepository` port (not an extension of the existing `SkillRepository` trait — kept separate so the existing 10-method trait doesn't grow with an unrelated concern, matching how `agent_runtime` already prefers many small ports over one large one): `bind_api_agent`, `unbind_api_agent`, `api_agent_bindings` (for UI), `enabled_skills_bound_to_api_agent` (mirrors `enabled_skills_bound_to`'s query shape against the new table). Implemented by `SqliteSkillRepository` (same struct, second trait impl block, same `NativeDatabase` connection).
- [x] 2.3 `SkillApplicationService` gains an `api_bindings: Arc<dyn SkillApiBindingRepository>` field and methods: `bind_skill_to_api_agent` (validates the Skill exists via `load()` and the agent id is registered via a new `ensure_known_agent` check against `agent_mount_configurations()` — that query already returns every agent id via a `LEFT JOIN agents`, CLI or API, so it's a correct reuse, not a CLI-specific check), `unbind_skill_from_api_agent`, `list_api_agent_bindings`, and `bound_skill_prompts_for_api_agent` (reads bound Skills, then `filesystem.read_source` + a new `strip_frontmatter` helper per Skill — **significant design correction**: a Skill's instructional *body* text is never persisted to SQLite, only to its `SKILL.md` file; `metadata.description` is a short unrelated catalog blurb, confirmed by reading the 6 built-ins' actual definitions, so body extraction requires a filesystem read + frontmatter strip, mirroring `preview_skill`'s existing `read_source` pattern). `SkillApi` facade extended with matching public methods. `bootstrap/skills.rs` updated to construct the repository once and pass it as both `Arc<dyn SkillRepository>` and `Arc<dyn SkillApiBindingRepository>`.
- [x] 2.4 Unit tests (11 total: 6 repository-level in `sqlite_repository.rs`, 5 doubles/service-level in `application/tests.rs`, using a new `SkillApiBindingRepository` impl on the existing `FakeRepository`): bind/unbind round-trip; binding an already-bound Skill updates rather than duplicates; unbinding a never-bound pair is a no-op; `enabled_skills_bound_to_api_agent` excludes a disabled Skill; cascade delete when the Skill is deleted; binding to an unknown agent id is rejected; `bound_skill_prompts_for_api_agent` strips frontmatter and excludes a disabled Skill; unbind removes a Skill from the bound list.

## 5. `agent_runtime`: `execute()` integration

- [x] 5.1 `execute()` calls a new `resolve_system_prompt(agent_id, skills, logging, clock, request)` helper right after resolving `wire_format` (before the history fetch), which calls `skills.bound_skill_prompts(agent_id)` and formats non-empty results via a new `format_system_prompt` helper (`## <name>\n<body>` per Skill, joined with blank lines); on lookup failure, logs a `Warn`-level `AgentLog` and returns `None` rather than failing the generation.
