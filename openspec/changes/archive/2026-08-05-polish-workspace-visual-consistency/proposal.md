## Why

A systematic visual walkthrough of the running app (main workspace, all 9 session tabs, all 14 settings pages, Loop Center, both `futuristic`/`minimal` styles, and narrow desktop widths) surfaced concrete gaps between the app's own `visual-design-system` rules and what actually ships. The most visible gap is Loop Center rendering with no panel/card chrome at all, unlike every other surface, which reads as unfinished. A few smaller layout, timing, and messaging inconsistencies showed up in the same pass. Fixing these closes real, observed gaps rather than a hypothetical audit.

## What Changes

- Loop Center's three-column layout (循环工程 nav / main content / 检查器) adopts the same shared panel/card token treatment (`.ucd-panel` / `.ucd-card` family) that the workspace shell and every settings page already use, in both `futuristic` and `minimal` styles.
- The MCP settings page's plain-text `-- 用户配置 --` / `-- 项目配置 --` group separators are replaced with the standard styled section-header treatment already used elsewhere (e.g., Basic Settings' grouped section headers).
- The workspace top bar keeps a reachable search entry point at widths at or below 900px instead of the search input disappearing with no replacement affordance.
- Toast notifications (e.g. "会话创建成功") reliably auto-dismiss within their configured duration instead of visibly persisting across multiple subsequent navigations.
- The Agent Terminal's web-mock "local CLI unavailable" notice renders as one localized message instead of printing both a Chinese and an English line for the same notice.
- The session info panel (会话信息面板) stops nesting bordered field/metric rows inside an already-bordered container — replaces the current card-in-card pattern with unframed rows, consistent with the project's existing "no nested card-in-card" rule.
- The session sidebar's batch-management and archived-view controls move out of their own dedicated full-width rows into a compact/overflow control, so the session list — the sidebar's most-used element — gets more of the available vertical space.
- Basic Settings' "高级配置" (Advanced configuration) disclosure no longer nests four independently-bordered cards (network proxy, data & storage, logs, Node environment) inside its own already-bordered container — each sub-topic renders as a plain labeled section instead.
- The workspace-defaults "管理工作区打开工具" expandable panel reuses the shared `SettingsDisclosure` component instead of a page-local hand-rolled `<details>` implementation that had already started drifting from it.
- The CLI Management page ("CLI 管理") no longer shows "全部升级 N" twice — once as the real header action button and once as inert duplicate text inside the "本地环境检查" info row.
- The CLI Parameters page's ("CLI 参数") agent picker stays visible while scrolling through a longer parameter list (e.g. Codex CLI's 6 parameters) instead of scrolling out of view, so switching agents no longer requires scrolling back to the top first.
- The MCP Servers page's ("MCP 服务器") add/edit form and import/export dialogs use the shared `ApplicationDialog` component instead of a hand-rolled overlay — they now have proper dialog semantics (`role="dialog"`, `aria-modal`, `aria-labelledby`), a working Escape-to-close, a focus trap, and focus restoration on close, matching every other dialog in the app built on that primitive. The server card's enable/disable toggle also gets an explicit accessible label, matching every other icon-only control in this app.
- The Agent Configurations page's ("Agent 配置") OnePiece tab no longer wraps its content in an extra bordered card that its three sibling tabs (Claude Code / OpenCode / Codex CLI) render without, and it gains the same local "search saved profiles" input its siblings already have — closing both a visual card-in-card gap and a functional parity gap between tabs of the same page.
- The Skill Management page's ("Skill 管理") skill list uses the same panel treatment regardless of which navigation item is selected — previously the "全部"/"未分配" views rendered a plain bordered box while a specific-Agent view rendered the shared glass-panel treatment. The filter toolbar's local search input (previously removed in a prior refactor, per design.md decision 14) is restored at the user's request after confirming the removal's history.
- The Prompt Hook page's ("Prompt Hook") four dialog/overlay states (preview, delete-confirm, create/edit form, and the advanced draft/version/evaluation panel) now use the shared `ApplicationDialog` component instead of two independent hand-rolled overlays — they gain proper dialog semantics (`role="dialog"`, `aria-modal`, `aria-labelledby`), a working Escape-to-close, a focus trap, autofocus on the first meaningful field, and focus restoration on close, matching every other dialog in the app.
- The Prompt Hook page's filter toolbar no longer squeezes its search input to the point of truncating its own placeholder text at common laptop widths (~1024–1279px) — its multi-column layout now activates at the same breakpoint the card list already uses for its own column switch. The "当前显示 N / M" result-count summary now sits directly under the filters instead of after the entire card list, so it updates visibly without scrolling.
- The SSH Connections page's ("SSH 连接") add/edit dialog now uses the shared `ApplicationDialog` component instead of a hand-rolled overlay — proper dialog semantics, working Escape-to-close, and autofocus. Its connection cards' test-status badge ("未测试"/"成功"/"失败") now actually renders in color: it previously referenced a CSS class that doesn't exist anywhere in the stylesheet, so it silently rendered with a fully transparent background regardless of status. The dialog also no longer shows every field's validation error the instant it opens on a blank form — errors now only appear after a first save attempt.
- The Extensions page's ("扩展能力") install-preview dialog now traps focus and closes on Escape (it already had correct static ARIA attributes, but none of the interactive dialog behavior). Its framework list no longer nests bordered cards inside another bordered card. Its status badges ("已安装"/"运行中"/"异常"/"当前环境不支持" etc.) now actually reflect their real status color — the shared `StatusPill` component inferred color by pattern-matching English words inside the *translated* status text, so in the app's primary zh-CN locale nearly every status (including error states) silently fell back to a green "success" color. This also fixes the same bug on the SDK Dependencies page, which uses the same shared component.
- The Plugin Integrations page's ("插件集成") integration list no longer nests a bordered card inside another bordered card — the same shape as the Extensions fix above, found on this sibling page during the same-session review.
- The Execution Observability page's ("执行可观测性") "MCP 观测能力" section no longer nests its four per-agent capability chips inside another bordered card, and now has an icon avatar consistent with the page's other three sections (it was previously the only one without one).
- The Usage Statistics page's ("使用统计") "每日趋势" and "Agent 使用量" sections no longer nest their charts/rows inside another bordered card, and the "Agent 使用量" column no longer stretches to an artificially tall, mostly-empty height to match its taller sibling column.

## Capabilities

### New Capabilities
(none — this change only tightens existing surfaces against already-documented rules)

### Modified Capabilities
- `visual-design-system`: add explicit Loop Center panel/card token coverage (parallel to the existing floating-assistant auxiliary-surface scenarios), require settings page group separators to use the standard section-header treatment instead of raw text dividers, formalize the existing "no nested card-in-card" project rule as a testable scenario, and require settings disclosures to avoid nested sub-panel cards and duplicate expand/collapse implementations.
- `main-layout-ui`: workspace top bar search must remain reachable (not simply removed) at responsive widths at or below 900px, and session sidebar secondary controls (batch management, archived view) must not each consume a dedicated full-width row ahead of the session list.
- `notification-system`: toast auto-dismiss must reliably elapse within its configured duration regardless of subsequent in-app navigation.
- `agent-terminal-runtime`: the web-mock unavailable-local-CLI notice must render as a single localized message rather than duplicated bilingual lines.

## Impact

- Frontend-only change (React + Tailwind), affecting both the Tauri desktop runtime and the browser Web/mock runtime since the touched components and `src/styles.css` tokens are shared across both.
- Likely files: `src/loop-center/loop-center.tsx` and related Loop Center components, `src/settings/pages/mcp-page.tsx`, `src/main-layout/top-bar.tsx`, `src/notifications/notification-provider.tsx` (or its toast component), `src/session-workspace/agent-terminal-tab.tsx`, `src/main-layout/session-info-panel.tsx`, `src/main-layout/session-sidebar.tsx`, `src/settings/pages/page-parts.tsx`, `src/settings/pages/network-proxy-section.tsx`, `src/settings/pages/data-management-section.tsx`, `src/settings/pages/log-management-section.tsx`, `src/settings/pages/folder-openers-section.tsx`, `src/settings/pages/basic-settings-page.tsx`, `src/settings/pages/providers-page.tsx`, `src/settings/pages/cli-parameters-page.tsx`, `src/settings/pages/mcp/mcp-server-form.tsx`, `src/settings/pages/mcp/mcp-import-export.tsx`, `src/settings/pages/mcp/mcp-server-card.tsx`, `src/settings/pages/agents/onepiece-configuration-panel.tsx`, `src/settings/pages/skills/skill-card-list.tsx`, `src/settings/pages/skills/skill-filter-toolbar.tsx`, `src/settings/pages/prompt-hooks/prompt-hook-dialogs.tsx`, `src/settings/pages/prompt-hooks/prompt-hook-lifecycle-panel.tsx`, `src/settings/pages/prompt-hooks/prompt-hook-filter-toolbar.tsx`, `src/settings/pages/prompt-hooks-page.tsx`, `src/settings/pages/ssh/ssh-connection-form.tsx`, `src/settings/pages/ssh/ssh-connection-card.tsx`, `src/settings/pages/extensions-page.tsx`, `src/settings/pages/sdk-page.tsx`, `src/settings/pages/plugin-integrations-page.tsx`, `src/settings/pages/observability-settings-page.tsx`, `src/settings/pages/usage-statistics-page.tsx`, `src/settings/pages/usage/usage-trend.tsx`, `src/settings/pages/usage/usage-agent-breakdown.tsx`, and `src/styles.css` if a shared section-header utility is needed.

- Visual QA must cover representative screens in both `futuristic` and `minimal` styles per the existing `visual-design-system` requirement.
