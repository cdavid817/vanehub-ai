## 0. Recovery note

This change's implementation was originally done directly in the main repo checkout (uncommitted) in an earlier session. That session then created a separate git worktree for an unrelated feature (`add-terminal-usage-tracking`); a worktree starts from the last commit on its branch and does not carry over another checkout's uncommitted working-tree changes, and all subsequent work continued in the worktree exclusively. The original uncommitted changes in the main checkout were never reconciled and were lost by the time that worktree's branch was merged back — confirmed empirically before redoing any work: `GenerationProcessEvent::Completed`/`ProviderOutputEvent::Completed` were still bare unit variants, `complete_claimed()` unconditionally built an `Estimated` record, and the frontend's `summaryWithLiveReportedTokens` fallback was untouched, despite this file previously marking all of section 1-4 as done. Tasks 1-4 below describe the actual, freshly-redone implementation, verified against the current `main` branch state.

## 2. Reported-vs-estimated precedence (`agent_runtime` application + `sessions`)

- [x] 2.1 Added `ReportedUsageTotals` (application-layer type, `models.rs`) and `normalize_provider_usage()` (`process_adapter.rs`) converting `ProviderReportedUsage` → `ReportedUsageTotals` at the infrastructure/application boundary — mirrors the existing `normalize_provider_tool()` conversion, keeping `agent_runtime::application` free of an infrastructure-defined type. `ProcessMonitor::run()` captures usage from the per-line `ProviderOutputEvent::Completed(Option<ProviderReportedUsage>)` into a local (alongside the existing `terminal_error` local) and attaches the normalized copy to the terminal `GenerationProcessEvent::Completed(Option<ReportedUsageTotals>)` it constructs from the exit code — two hops, not one, matching the two structurally-disconnected "Completed" events design.md's Decision 0 describes.

- [x] 2.3 Confirmed `AgentUsageAccountingKind`, the extended `AgentUsageRecord` (`cache_read_count`/`cache_creation_count`/`accounting_kind`), `sessions_gateway.rs::session_usage()`'s mapping to `SessionUsageAccountingKind`/`SessionUsageUnit`, and the `dead_code` removal on `SessionUsageAccountingKind::Reported`/`SessionUsageUnit::Tokens` in `sessions/application/models.rs` were already present and correct on `main` (landed via the sibling `add-terminal-usage-tracking` change, which shares this same seam) — no changes needed here.
