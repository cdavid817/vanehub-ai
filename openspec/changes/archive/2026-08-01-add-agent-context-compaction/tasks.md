## 1. Research & groundwork

- [x] 1.1 Confirm `bounded_count` (referenced from `AgentRuntimeApplicationService::complete_claimed`) — read its exact behavior to pick consistent, sane defaults for `COMPACTION_TRIGGER_CHARACTERS`/`COMPACTION_KEEP_RECENT_TURNS` rather than inventing unrelated numbers. **Finding:** `bounded_count` is just a `usize -> i64` saturating conversion (`i64::try_from(value).unwrap_or(i64::MAX)`) — no precedent for specific threshold values. Picked `COMPACTION_TRIGGER_CHARACTERS = 60_000` (~well under a 128K-token window even at a pessimistic ~1 char/token) and `COMPACTION_KEEP_RECENT_TURNS = 6` as conservative, documented defaults.
- [x] 1.2 Confirm the exact `RichBlock`/`RichCardBlock` JSON shape both wire-format-agnostic persistence (`sessions.append_rich_block`) and the frontend (`RichBlocks` component, `RichCardBlock` type) expect, so the compaction notice's `Value` is well-formed on the first attempt. **Finding:** `{ id, kind: "card", v: 1, title, bodyMarkdown?, tone?, fields?, meta? }` (`src/types/chat.ts`'s `RichCardBlock`); mirrored exactly in `compaction_notice_block`.
- [x] 1.3 Confirm both `anthropic_provider.rs`/`openai_compatible_provider.rs`'s `translate_sse_data` can be driven to accumulate full text (rather than forwarding `Token` events to a sink) with no changes to either function itself — the summarization helper should only need to change how its *caller* consumes the returned events, not the translation functions. **Confirmed:** both take `(&str, &mut ToolCallAccumulator) -> Option<GenerationProcessEvent>` with no I/O; `summarize_turns` reuses them unmodified, matching `Token(text)` to accumulate into a `String` instead of forwarding to `sink`.

## 2. Domain & application layer (`agent_runtime`)

- [x] 2.1 Add `COMPACTION_TRIGGER_CHARACTERS`/`COMPACTION_KEEP_RECENT_TURNS` constants (infrastructure-layer, alongside `MAX_TOOL_ROUND_TRIPS` in `api_process_adapter.rs`, not domain/application — this is adapter-internal policy, not a domain concept).
- [x] 2.2 Add a pure function computing accumulated character count from a `&[Value]` turns list and a pure function deciding whether to trigger, given that count — unit-testable without I/O, matching the `risk_tier_for`-style precedent from Phase 2. **Design correction:** implemented as a *recursive* walk of every string leaf in each turn (`turns_character_count`/`value_character_count`), not just the top-level `content` field as originally worded — both wire formats' tool-loop turns nest large payloads (tool results, tool-call arguments) inside arrays/objects rather than a flat `content` string, so a shallow field-only count would miss exactly the large payloads (e.g. file-read tool output) that motivate compaction in the first place. Covered by `turns_character_count_sums_nested_string_values_not_just_the_content_field`.

## 3. Infrastructure: summarization call

- [x] 3.1 New function `api_process_adapter.rs::summarize_turns`: builds a summarization request via `wire_format.build_request_body` (turns-to-summarize plus one instruction turn asking for a concise recap, no tools declared), sends it via the existing `blocking_http_client`, and reads the SSE response accumulating full text via `wire_format.translate_sse_data` instead of forwarding to a sink.
- [x] 3.2 Failure handling: if the summarization call itself fails (network error, non-2xx status), fall back to *not* compacting this round rather than failing the whole generation — a failed summarization attempt should not break an otherwise-working conversation. Log the failure through the existing `AgentLoggingPort` (required threading `logging`/`clock` into `execute()`, previously only available in `run_generation`).
- [x] 3.3 Unit/infrastructure tests: summarization request omits `tools`; accumulates text across multiple streamed chunks; failure path returns the "don't compact" fallback rather than propagating a hard error. Used a local `TcpListener`-based HTTP fixture (mirroring the existing pattern in `contexts::tooling::mcp::infrastructure::relay_tests`), pointed at via the OpenAI-compatible wire format (the Anthropic branch's endpoint is a hardcoded constant, not testable against a local fixture).
