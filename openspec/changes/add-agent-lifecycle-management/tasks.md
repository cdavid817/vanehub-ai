## 3. `agent_runtime`: facade and credential rotation

- [x] 3.1 `AgentRuntimeApplicationService::update_api_agent`: validates non-empty display name/model id, reads the *stored* `interface_format` via `provider_config` (404-style `AgentNotFound` if the id doesn't resolve to one), requires `base_url` only when that stored format is `openai-compatible`. `new_api_key: Some(key)` (trimmed, rejected if empty) stores via `credentials.store` *before* calling `api_agents.update` with a freshly-normalized `UpdateApiAgentInput{new_api_key: None}` — mirrors `register_api_agent`'s exact `let normalized = ...` pattern (trimmed/validated locals in a fresh struct, not the raw input passed through).

- [x] 3.4 5 application-layer tests added to `application/tests.rs`, extending `FakeWorld` with new configurable/observable state (`provider_config: Mutex<Option<ApiProviderConfig>>`, `updated_agents`/`deleted_agent_ids`/`stored_credentials`/`removed_credentials` recording `Mutex<Vec<_>>`s, `delete_api_agent_failure: AtomicBool` toggle) — all mirroring `FakeWorld`'s own established Mutex/AtomicBool-toggle conventions. **Note**: `register_api_agent` itself has no existing application-layer tests at all (`FakeWorld::register` deliberately errors, "does not support API agent registration") — a pre-existing gap this change doesn't need to close, but it meant `FakeWorld`'s `ApiAgentGateway`/`ApiCredentialPort` impls needed real (not `unimplemented!`) behavior added from scratch for `update`/`delete`/`store`/`remove`, not just extended. ## 5. Frontend

- [x] 5.1 **Design gap found and fixed before writing any frontend code**: `AgentRegistryEntry`/`AgentView` never carried `modelId`/`interfaceFormat`/`baseUrl` (they only ever lived behind the separate `ApiAgentGateway::provider_config` port method, used internally by generation start-up) — meaning the edit form would have had no way to pre-fill an agent's current values, or even know whether `baseUrl` is required, without a new read path. Added a small additive read-only slice to close this: `AgentRuntimeApplicationService::api_agent_provider_config` → `AgentRuntimeApi::api_agent_provider_config` → `dto::ApiAgentProviderConfig` + `mapper::api_agent_provider_config_to_dto` → new `get_api_agent_provider_config` Tauri command → `types/agent.ts`'s `ApiAgentProviderConfig` → `agent-service.ts`'s `getApiAgentProviderConfig`/`tauri-agent-client.ts`. This doesn't change any previously-implemented write behavior; it's the read-side counterpart the edit UI needs. `types/agent.ts`'s `UpdateApiAgentInput` also added here as originally planned.
- [x] 5.2 `agent-service.ts`: `getApiAgentProviderConfig`/`updateApiAgent`/`deleteApiAgent` interface methods added.
- [x] 5.3 `tauri-agent-client.ts`: `invoke("get_api_agent_provider_config"|"update_api_agent"|"delete_api_agent", ...)` implementations added.
- [x] 5.4 `web-agent-client.ts` mock: new `webApiAgentProviderConfigs: Map<string, ApiAgentProviderConfig>` module-level map (mirroring the real backend's separate-read-path shape — `AgentRegistryEntry`/`mockAgents` still don't carry these fields either), populated by `registerApiAgent`, read by `getApiAgentProviderConfig`, mutated by `updateApiAgent` (re-validates against the *stored* `interfaceFormat`, matching the real backend). `deleteApiAgent` checks 4 of the real backend's 5 categories — **`usage_records` has no mock equivalent to check** (the mock has no separate usage-record store distinct from sessions/messages) and is skipped; the other 4 (`sessions`, `webAgentMemories`, `loopDefinitions` as worker, `loopDefinitions` as verifier) are checked, matching the real backend's itemized-rejection shape, before removing the `mockAgents` entry (via `.splice`, not reassignment — `mockAgents` is imported as `const`, mutated in place exactly like the pre-existing `registerApiAgent`'s `.push()` already does), the provider-config map entry, and `webSkillApiAgentBindings` rows.
- [x] 5.5 3 new tests in `web-agent-client.test.ts`: update round-trips `displayName`/`modelId`/`baseUrl` through `getApiAgentProviderConfig`; update rejects a missing base URL against a stored openai-compatible format; delete succeeds for an unreferenced agent (confirmed via both `getApiAgentProviderConfig` returning `null` and absence from `listAgents()`) and is rejected for one with an associated session.
