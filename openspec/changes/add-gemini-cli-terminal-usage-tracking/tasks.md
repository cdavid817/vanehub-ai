## 1. Project-slug lookup and session file resolution

- [x] 1.1 Added `find_gemini_chat_session_since(working_directory, since_ms)` in `infrastructure/providers/session_capture.rs`, mirroring `find_opencode_session_since`/`find_codex_rollout_since`: reads `~/.gemini/projects.json` via `read_gemini_project_slug`, lists `.jsonl` files under `~/.gemini/tmp/<slug>/chats/`, filters by mtime >= `since_ms` (2-second grace buffer, matching the existing pattern), returns the most-recently-modified match.
- [x] 1.2 Added `gemini_home_dir()` (`~/.gemini`, no env var override — verified no such override exists in the installed package's source) and `gemini_projects_registry_path()` (`~/.gemini/projects.json`).
- [x] 1.3 Unit tests in `session_capture_tests.rs` (via the `pub(super)` `read_gemini_project_slug` helper, which takes an explicit registry path so it's testable without touching the real home directory): `gemini_project_slug_resolves_a_matching_registered_path`, `gemini_project_slug_returns_none_for_an_unregistered_path`, `gemini_project_slug_missing_registry_file_is_graceful`. Path matching reuses the existing `paths_match()` helper (already slash/case-insensitive on Windows), so no separate Windows-case-variance test was needed — that behavior is already covered by `paths_match`'s own existing test coverage from the codex-cli/opencode capture tests. `find_gemini_chat_session_since` itself is intentionally left without a direct unit test, matching the existing precedent: neither `find_codex_rollout_since` nor `find_opencode_session_since` has one either, since all three depend on real home-directory resolution that isn't practically mockable without a larger refactor; covered instead by 4.6's manual verification task.

## 2. Usage aggregation

- [x] 2.1 Added `aggregate_gemini_usage(path, file)` in `infrastructure/terminal_usage_ingestion.rs`: parses each JSONL line via a permissive `GeminiChatMessageLine { type, tokens }` struct (metadata/`$set` lines deserialize successfully with both fields `None` since serde ignores their unrecognized keys, so they fall through the `type == "gemini"` filter naturally — no special-casing needed), sums `tokens.input` into `input_tokens`, `tokens.output + tokens.thoughts` into `output_tokens`, `tokens.cached` into `cache_read_tokens`; `cache_creation_tokens` stays 0. `tokens.tool` is deliberately left unmapped (see design.md Decision 3).
- [x] 2.2 Added `ingest_gemini_terminal_usage(session_folder, started_at_ms, sessions, message_id, session_id, agent_id, clock)` following the exact same shape as `ingest_opencode_terminal_usage`/`ingest_codex_terminal_usage`.
- [x] 2.3 Fixture-based unit tests pinned to the exact shape read from `ChatRecordingService` source: `gemini_usage_sums_across_all_gemini_messages_and_folds_thoughts_into_output` (metadata line + `type: "user"` message + two `type: "gemini"` messages + a `$set` line, asserting only the two gemini messages contribute and `thoughts` folds into output), `gemini_usage_skips_gemini_messages_without_a_tokens_object`, `gemini_chat_session_without_any_gemini_messages_yields_zero_totals`.
