# 会话工作区证据控制台

会话旁边的九个标签——工作区、变更、文档、文件、终端记录、Shell、日志、链路、报告——是**一个**能力而不是九个，它们的共同点在于它们拒绝做什么。每一个回答的都是「已经发生的工作」的问题，每一个都可能被问到自己无法完整回答的问题。贯穿始终的设计规则是：**残缺的答案绝不能看起来像完整的答案**。

本章讲的是开发这些标签时需要、但无法从代码本身推断出来的五件事：fidelity 与 coverage 各自的含义、Shell 如何在被切走后存活、远端工作区在回答任何问题之前需要什么、日志如何建索引，以及一个面板如何把读者交给另一个面板。

## fidelity 与 coverage 是两种不同的坦白

这两者容易混淆，但回答的是不同的问题。

**fidelity** 是单条记录的属性：*我们是怎么知道这件事的？* 由记录的产出方设定，随记录一起流转。四个等级见[执行可观测性](execution-observability.md)；这里要紧的是：控制台从不推导它、从不上调它、也从不展示一条没有它的记录。

**coverage** 是一个答案的属性：*你问的范围里，有多少被真正看过了？* 它挂在页面上，而不是单独去取——否则读者可能看到的是某一时刻的行，配上另一时刻的覆盖度声明。

| coverage 状态 | 读者据此可以得出的结论 |
| --- | --- |
| `complete` | 范围内的一切都被检查过。空结果意味着确实什么都没有。 |
| `indexing` | 展示的行是真的；集合还未最终确定。 |
| `partial` | 范围内有东西没被检查。空结果什么也不意味着。 |
| `unavailable` | 这个问题无法作答。 |

coverage 只会降级，每次降级都追加一个稳定的 reason code——永远不是散文，因为读者按 code 分组，而自由文本无法分组。一个丢过事件、遇到源冲突、有行被保留策略裁掉、或者读的投影落后于日志的页面，会为每一项各给出一个 code。

**最重要的区分是「这就是全部」与「这是被看过的部分」。** 它们是两个独立的事实，有各自的补救办法，把两者渲染成同一个样子就等于扔掉了其中一个。这也是为什么空列表旁边有 `partial` 时永远不说「无结果」——那是查询没有资格给出的结论。

### 缺失不是零

推导不出来的数字是**缺失**，不是默认为零。`reportedTokens` 缺失表示没人报告过 token；`reportedTokens: 0` 表示有人报告了零。Rust 模型用 `Option` 配 `skip_serializing_if`，前端渲染一个具名的缺失——「未观测」「不可用」「已脱敏」——而不是一个破折号，因为这是三件不同的事，而其中一件意味着这项工作可能并非行里暗示的那样发生过。

### 历史活动是投影，从不写入

早于证据日志的会话，历史里仍有 `message.toolUse` 块，控制台会展示它们——作为独立的列表，恒为 `inferred`，恒为部分覆盖，标明来自消息历史。

它们**不会**被写进日志。`toolUse` 块是助手声称自己在做什么；日志装的是运行时看着发生的事。两者一旦归档在一起，下游就再也分不开。这一点有守卫强制：任何文件都不得同时向日志追加并读取聊天语料；一条迁移测试要求：一个已经存有此类消息的数据库，迁移后日志必须是空的。空在这里是正确答案，而它恰恰看起来像 bug。

## Shell 的 attach 与 detach

Session Shell 是一个长驻进程。标签只是它的一个**视图**，两者生命周期独立。

`SessionShellRegistry` 是唯一能开关 shell 的东西——由构造层面保证，因此不存在第二个「注册表不知道」的 shell 创建点。切走会 detach 视图；进程继续运行、继续产出输出，读者回来时它还在。**一次构建能挺过标签切换、会话切换和重挂载，只有被明确要求时才停止。**

前端作者需要知道的：

- **不要在 unmount 时 kill。** 被淘汰的 one-view 服务就是这么做的，结果有人点了另一个标签，后台构建就死了。守卫会让任何重建它的生产文件失败。
- **重新 attach 会重放。** 注册表保留近期输出，所以回来的视图不是空白，也不是第二个进程。
- **能力来自 runtime descriptor**，一个前端按 `kind` 收窄的内部标记联合。每个变体只带它真正具备的能力——模拟 shell 没有 resize，PTY 没有 reconnect。被它取代的字符串联合让 UI 两个都能要。

## 远端工作区需要 helper，并且会在你发问之前说明

远端工作区通过对端的 helper 回答与本地相同的问题。它并不总是在，而它的缺席是一种正常状态，不是错误。

provider **逐能力**报告自己能做什么，而不是一个总开关：一台有 Git 但没有 ripgrep 的远端主机是常态，一个总开关要么藏起搜索的缺口，要么把能用的四件事一起禁掉。每项能力自带状态，不可用时附一个稳定的 reason code，对应 `workspace.capability.reason.*` 翻译——绝不是一段消息。

不支持的操作渲染为**带原因的禁用**而不是隐藏。一个在远端工作区里消失的控件会让读者以为自己记错了位置；一个明确显示不可用的控件告诉他们真相，即这个工作区在另一台机器上。连接本身如何建立与验证见 [SSH 连接](ssh-connections.md)。

## 日志索引

日志标签只读索引。没有回退到扫文件的路径：回退等于第二套查询实现，有不同的过滤器、不同的边界、不同的覆盖度语义，而它恰恰在读者最难判断「是谁回答的」时被触发。索引答不了的时候，它会直说。

索引是[持久化与统一日志](persistence-and-logging.md)中所述的脱敏 JSONL 文件之上的**可重建投影**。其中没有任何东西是第二真相源——每一行都能从文件重新推导，这正是它的 schema 可以为「读」而设计的原因。

一个修复任务负责让它跟上：

- **在窗口存在之后启动，是 spawn 而不是直接跑**，并且交给 blocking 池而不是在 async worker 上执行。同步 SQLite 跑在 runtime worker 上会把它 park 整个扫描时长，所有无关命令排在后面，而唯一的症状只是「启动后有几个命令慢了一次」。
- **进度是持久化的 checkpoint**，按目录 generation 而非路径作键。轮转后的文件会复用路径，所以按旧 offset 续跑会静默跳过新文件的开头。
- **每一批都有界**，且读文件时不持有任何事务。跨文件 IO 持有的事务会把写锁占满磁盘耗时那么久。
- **运行期间查询以 `indexing` 覆盖度作答**，并报告索引已推进到的位置，好让一个滞后的页面能自我解释。

分页是 keyset，并且保持 keyset。这个结果集在读者眼皮底下增长；offset 会随每次插入重编号，因此 offset 分页恰好跳过读者阅读期间到达的那些行，而且是静默跳过。

保留策略会删掉源文件已不在保留清单中的索引行——并在同一个事务里记一条 `log_source_expired` gap。这是此处唯一不可撤销的删除，因为可供重读的文件已经没了；于是轮转之后的查询报告的是部分覆盖，而不是一个自称完整的残缺答案。

## 跨面板导航

这些标签是同一个会话的不同视图，顺着线索走的读者不该需要自己重建刚才在哪。面板间的导航是一个**scope**，不是一条路由：目标标签，加上把读者带到那里的关联——run、operation、command、文件路径、span。

新增一条链接必须遵守的规则：

- **传关联，不传结果。** 链到「这条命令的日志」应传 command id，让日志标签用自己的边界和自己的覆盖度去问自己的问题。把行传过去，等于用一个面板的名义呈现另一个面板的边界。
- **只有关联可信时才提供链接。** 证据在**其权威归属方提供了关联**时才暴露到文件变更、审查决定、验证结果和用量观测的链接——绝不在「看起来像」的时候。
- **目的地陈述自己的覆盖度。** 通过链接抵达，不会让那个面板对自己答案的坦白打折。
- **导航是一次服务边界调用**，和前端其它一切一样。组件从不直接触碰 Tauri，见[运行时与服务边界](runtime-boundaries.md)。
