# Runtime 与功能状态标签

本指南每一章开头都有一行状态标签。这一页讲怎么读它们。

## 两类标签

**它们回答两个不同的问题**，容易混在一起：

| 问题 | 用哪类标签 |
| --- | --- |
| 这个功能做完了吗？ | 功能状态：已实现 / 预览 / 规划中 |
| 我现在这个环境里它真的生效吗？ | Runtime：仅桌面端 / 仅 Web/mock |

一个功能可以「已实现」但「仅桌面端」——做完了，只是浏览器里不生效。

## 功能状态

| 标签 | 含义 |
| --- | --- |
| **已实现** | 已实现用户可见路径，并有验证证据 |
| **预览** | 支撑 contract 已存在，但正常工作流尚未完成 |
| **规划中** | 尚无受支持工作流 |

**「预览」不等于「快好了」**。它的准确含义是：底层服务或 mock contract 存在，但你在界面上走不完整个流程。判断一个功能是否可用，看的是有没有**用户可见路径**，而不是代码里有没有相应的实现。

## Runtime

| 标签 | 含义 |
| --- | --- |
| **仅桌面端** | 使用本地文件系统、CLI、SQLite 或 OS 集成的 Tauri runtime |
| **仅 Web/mock** | 确定性浏览器模拟，不产生 native side effect |

## 你现在在哪个 runtime

**装了桌面应用打开的就是桌面端**；在浏览器里访问的是 Web 预览。

两者界面完全一样——这是有意的，同一套 React 代码服务两种运行时。**所以不能靠界面长相判断**。

## 浏览器预览里不生效的能力

**这些一律需要桌面端**：

| 能力 | 桌面端 | 浏览器预览 |
| --- | --- | --- |
| 启动 CLI 进程 | 是 | 否 |
| 终端（PTY） | 是 | 否 |
| 数据持久化（SQLite） | 是 | 否 |
| 读写文件 | 是 | 否 |
| 系统凭据存储 | 是 | 否 |
| SSH / IM 网络连接 | 是 | 否 |
| 托盘 / 通知 / 开机自启 | 是 | 否 |
| 权限拦截 | 是 | 否 |
| 执行链路采集 | 是 | 否 |
| 界面与交互逻辑 | 是 | 是 |

**最后一行是关键**：界面和交互在两种 runtime 里都是真的，其余都不是。

## 「操作成功了」不等于「真的发生了」

**浏览器预览里的成功提示只证明界面逻辑正确**。它用的是确定性的模拟数据——同样的操作每次得到同样的结果，因为结果是写死的，不是算出来的。

具体说，在浏览器预览里：

- 创建会话会成功，但**没有进程被启动**
- 终端会输出内容，但**那是模拟的，不是命令的真实输出**
- 保存设置会提示成功，但**关掉页面就没了**，因为没有数据库
- CLI 显示「已安装」，但**没有检测过你的机器**

这些不是 bug。浏览器预览的用途是验证界面、做文档截图、快速看产品长什么样，不是代替桌面端。

## 本指南的截图

**所有截图都在浏览器预览里拍的**（固定的 CI 环境，保证可重复）。

所以：**截图可以说明「这个界面长什么样、控件在哪」，但不能作为「真的启动了进程 / 写了文件」的证据**。涉及原生副作用的说明以正文为准，不以截图为准。
