# 常见问题

## VaneHub AI 会替我管理 API Key 吗？

**外部 CLI 的不会**。Claude Code、Codex CLI、Gemini CLI、OpenCode、Antigravity CLI 的 Provider 认证由各自 CLI 管理，凭据存在它们自己的位置，VaneHub AI 不会要求你输入 Provider 密码。Antigravity CLI 更进一步——它走 Google 登录并把凭据存进系统钥匙串，配置档里根本没有密钥字段。

**OnePiece 的会**。原生 API Agent 的 API Key 由 VaneHub AI 保存，见[原生 API Agent](native-agent.md)。

## 为什么我的 Agent 没有记忆？

大概率是**没有配置 OnePiece 的 provider**。

CLI Agent 的记忆提取由 OnePiece 代做——未配置时不会产生任何记忆。即使你主力用 Claude Code，也需要先配好 OnePiece。详见[个性化配置](personalization.md#两个必须知道的前提)。

## 能让某个 Agent 有独立的记忆吗？

**不能**。当前记忆是主机级共享池，一个 Agent 记下的内容其他 Agent 也能用。如果需要隔离，只能整体关闭记忆。

## recall 能搜到我的项目代码吗？

**不能**。它检索的是你积累下来的**记忆**，不索引仓库文件。

## 「只读」模板是不是什么都不让做？

不是。**读文件与写记忆在所有档位下都放行**——即使「只读」。它拒绝的是**写文件**与**执行命令**。

## 「信任」和「Yolo」有什么区别？

**实际策略规则完全相同**。区别只在赋予时的确认强度：两者都需要显式确认，但 Yolo 的提示更强。

## 多 Agent 模式是不是还没做好？

**已经可用**。在创建会话对话框里选择**多 Agent**即可分配席位。早期版本中它确实被禁用过，那部分文档已过时。

需要注意的是：早期设计的「依赖图 / DAG 编排」**已被移除**，现在的形态是[群聊席位 + `@` 交接](multi-agent-workflow.md)。

## 有会话检查点或跨 CLI 会话迁移吗？

**没有**。当前不支持把一个会话的上下文迁移到另一个 CLI，也没有会话检查点功能。会话与创建时选定的 Agent 绑定。

## 为什么链路里有些节点展不开？

因为它是**不可见**保真度——那是外部 CLI 的内部行为，属于黑盒。系统只保留边界节点，**不会虚构子节点**。

想要可展开的完整调用链，用 OnePiece。详见[可观测性与日志](observability.md#保真度为什么有些节点展不开)。

## 能用链路 id 去搜日志吗？

**不能**。日志中刻意不包含任何执行标识符，这是隐私设计。两者需要用**时间**对上。

## 远程工作区能用 Loop 吗？

**不能**。Loop 在独立 Git worktree 中作业，而**远端不支持 worktree**。

## 定时任务在应用关闭后还会跑吗？

**关闭期间不会跑，但不会全部丢弃**。调度器在应用内运行，不是系统级服务。

界面上的说明是：因应用关闭而错过的运行会在**下次启动时补上，且只补最近一次**。所以关了三天、每天一次的任务，重启后只补跑一次。

## 用量统计准吗？

**数据来自各 CLI 自己的报告**，VaneHub AI 不独立计量 token。做成本核算前请先读页面上的口径说明。

## MCP 配一次能给所有 Agent 用吗？

**目前只有 Claude Code 与 Codex CLI 走中继**。Gemini CLI、OpenCode 与 Antigravity CLI 需要各自配置，且它们的 MCP 调用不会出现在执行链路中。

## 界面支持哪些语言？

五种：简体中文、English、繁體中文、日本語、한국어。在**设置 → 基础配置**中切换。

## 我想了解内部实现，看哪里？

本指南只讲怎么用。想知道这些机制**为什么这样设计**、内部如何实现，见[《VaneHub AI 开发者指南》](../../../developer-guide/zh-CN/src/index.md)——它面向开发者与贡献者，含架构说明与代码位置引用。
