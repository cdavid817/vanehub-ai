# Loop Engineering 工程：让 Agent 自己迭代到达成

## 什么是 Loop Engineering

**它是一台由运行时驱动的「改—验—判」循环机器。**

你给它一个目标和一组客观的必过检查，它就反复让一个 Agent 去改、跑检查、由另一个 Agent 审查结果，直到检查全过或触及你设定的上限——**然后停下来等你确认，永远不自己宣布成功**。

它解决的是「改完要跑测试，测试挂了要把失败贴回去再改」这种反复往返的手工成本。你付出的是一次配置，换来的是无人值守的迭代。

三个词概括它和别的机制的差别：

| | 谁在推进 | 停止条件 |
| --- | --- | --- |
| **Loop（本章）** | 运行时按固定阶段推进 | 检查全过 / 触及限额 / 无进展 |
| [多 Agent 群聊](multi-agent-workflow.md) | Agent 自己 `@` 下一位 | 提及耗尽 / 深度上限 |
| 普通会话 | 你每轮手工发消息 | 你不再发了 |

**Loop 的推进权在运行时手里，不在 Agent 手里**。这是它能强制执行限额、强制人工验收的前提——如果由 Agent 决定何时停，那些上限就只是建议。

## Loop 由什么组成

### 一个定义

定义是可持久化的配置，跨重启保留，带版本号。创建向导分**四步**：

| 步骤 | 填什么 |
| --- | --- |
| **目标与范围** | 名称、项目路径、基础分支、**目标**、**验收标准**（每行一项）、**允许路径**、**保护路径** |
| **角色智能体** | **执行智能体**与**验证智能体** |
| **验证与限制** | **验证命令**与各项限额 |
| **检查确认** | 复核后保存 |

**允许路径与保护路径决定它能碰什么**。这是范围约束，不是提示——路径范围不安全的定义会被直接拒绝。

**验收标准是给验证智能体读的判断依据**，与验证命令不是一回事：前者是文字描述的主观标准，后者是必须退出码为零的客观检查。

### 两个角色，两个 Agent，两个会话

这是 Loop 最容易被忽略的结构：**它不是一个 Agent 自己转圈，而是两个角色分工**。

| 角色 | 职责 | 约束 |
| --- | --- | --- |
| **执行智能体** | 按目标改代码 | 在独立 Git worktree 中作业 |
| **验证智能体** | 审查这一轮的产出 | **只读** |

验证智能体在**每轮的新会话**里拿到四样东西：不可变的目标、验收标准、有界的 Git 差异、以及检查证据。它返回一个结构化的结论：**已通过**、要求再改一轮、或**受阻**，并附带发现。

**验证智能体的写入会被拒绝**。它尝试写文件、执行会改动项目的命令、或改变运行状态时，运行时会拒绝该动作并记录一条脱敏诊断。这条约束的意义在于：审查者不能顺手把问题改掉，否则「审查通过」就失去了独立性。

两个角色都要选 Agent，缺一个不能保存（界面提示「请选择执行智能体和验证智能体」）。**能担任角色的 Agent 有准入条件**：

- 支持 CLI 交互的 Agent 直接可用
- **只支持 API 交互的 Agent 必须开启工具使用信任**，否则定义被拒绝，错误信息会明确指出这一点

### 验证命令是结构化记录，不是 shell 字符串

每条验证命令由五项构成，而不是一行命令文本：

| 字段 | 说明 |
| --- | --- |
| **验证程序** | 可执行文件 |
| **参数** | 每行一项 |
| **相对工作目录** | 相对运行工作树根 |
| **命令超时（秒）** | 单条命令上限 |
| **必需检查** | 是否必过 |

**这样设计是为了不拼接 shell**。命令解析到运行根之外、使用不被允许的可执行文件、或参数结构非法时，会被拒绝执行并让验证阶段失败——而不是拼成一行字符串交给 shell 去碰运气。

每条命令执行后会持久化退出状态、耗时、摘要和关联的操作 id 作为证据。

### 限额

| 限额 | 约束 |
| --- | --- |
| **最大迭代次数** | 必须在 1–20 之间，**硬性封顶 20** |
| **步骤超时（秒）** / **总超时（秒）** | 总超时不得小于步骤超时 |
| **连续运行错误限制** | 容忍多少次连续运行错误 |
| **连续无进展限制** | 容忍多少轮原地打转 |

## 它能做什么、不能做什么

**能做的：**

- 在独立 Git worktree 里反复改代码，直到一组客观检查全过
- 用第二个 Agent 独立审查每轮产出，而不是让改的人自己判卷
- 在触及任何限额时以明确原因停下，而不是无限跑下去
- 保留每轮的动作、检查证据、差异摘要供你事后核查
- 暂停后从持久化的阶段边界恢复

**不能做的：**

- **不能自己宣布成功**——最终必须由你接受或拒绝
- **不能在远程工作区运行**——它依赖 worktree，远端不支持
- **不能对非 Git 项目运行**——定义会被直接拒绝
- **不能自动提交、合并或推送**——它只在 worktree 里留下结果
- **不能突破 20 轮迭代上限**——没有配置项可以放开

定义在保存阶段就会被校验：**非 Git 项目、远程工作区、Agent 缺失、路径范围不安全、限额非法**，任一条命中都会被拒绝，且**不会启动任何 Agent、不会创建 worktree**。失败在配置期，而不是跑了一半才发现。

## 创建一个 Loop

![循环工程中心的三栏布局，尚无循环定义](assets/screenshots/loop-center-zh-CN.png)

界面分三栏：左侧是**定义**与**运行记录**，中间是主区域，右侧是**检查器**。首次进入时中间显示「暂无循环定义」。

1. 在左侧活动栏选择**运行**，切到**循环工程**标签。
2. 点左栏的 **+** 新建定义，按上面的四步向导填写。
3. 保存并启动。

## 一次迭代的五个阶段

每轮按固定顺序推进：**准备 → 执行 → 验证 → 决策 → 收尾**。

决策阶段按严格优先级短路：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 命中硬性终止原因 | 按原因归入等待验收 / 已取消 / 已失败 |
| 2 | 验证智能体给出**受阻** | 已失败 |
| 3 | **必需检查未全过** | 进入下一轮 |
| 4 | 验证智能体要求再改一轮 | 进入下一轮 |
| 5 | 以上都不成立 | 转入**等待验收** |

**必需检查排在验证智能体的意见之前**。客观的确定性检查压过主观判断——验证智能体说「可以了」但 lint 还挂着，照样得改。

反过来也成立：**任何必需检查失败或超时，这一轮就不会进入等待验收**。

## 强制人工验收

**这是 Loop 最重要的一条安全设计：自动循环永远不会自己宣布成功。**

即使判定为目标已达成，运行也只会进入**等待验收**状态。你不确认，它就停在那里。

达到最大迭代次数时同样如此，界面提示「已达到最大迭代次数，请接受或拒绝此结果」。

你有三个选择：

| 操作 | 效果 |
| --- | --- |
| **接受结果** | 结束，运行标记为已成功 |
| **拒绝结果** | 运行被取消，但**证据和工作树仍可供检查** |
| **根据反馈继续** | 填写下一次迭代的反馈，再跑一轮 |

第三个选项是实际最常用的：你看完产出，指出问题，让它带着你的反馈再迭代一次。

## 无进展检测

Loop 会比对每轮的目标状态，识别「原地打转」。**只要满足下面任意一条就算有进展**：

- 代码变更有实质改动
- 失败的检查换了一批
- **某项之前没过的检查现在过了**

第三条尤其有用：假设某轮只修好了 lint、没动别的文件，代码变更可能和上一轮一样，但「新通过了一项检查」会被识别为真实进展。

只有三个维度**全都没变化**，且连续次数达到你设定的容忍值，才会以无进展终止。

## 运行状态与控制

运行有七种状态：**排队中**、**运行中**、**已暂停**、**等待验收**、**已成功**、**已失败**、**已取消**。

右侧检查器显示当前的**阶段**、**状态**和**项目**。**运行控制**提供：

| 操作 | 行为 |
| --- | --- |
| **暂停** | **当前活动步骤会先完成或协调**，之后才暂停，不会硬切 |
| **恢复** | 从持久化的阶段边界继续 |
| **停止** | 活动进程立即取消；**已有证据和工作树继续保留** |

**暂停不是立刻生效的**。请求暂停后界面会提示「已请求暂停；当前步骤完成或协调后将暂停执行」——这是为了不在半途切断一个正在写文件的动作。

## 检视执行过程

| 想看什么 | 去哪 |
| --- | --- |
| 各轮阶段流转 | 时间线视图 |
| 单轮的动作与检查结果 | 迭代详情 |
| 这一轮执行者做了什么 | **执行摘要** |
| 验证智能体的结论与发现 | **验证者审查** |
| 整体运行状态 | 运行控制条 |

证据按角色区分**执行者**与**验证者**，状态有**等待中**、**已通过**、**失败**、**受阻**、**已取消**。

## 注意事项与限制

- **仅桌面端可用**，依赖本地进程执行验证命令与 Git。
- **迭代上限硬性封顶 20**，无法通过配置突破。
- **必须人工验收**——无人确认时运行会一直停在等待验收状态。
- **Loop 在独立的 Git worktree 中作业**，不污染主工作区；因此它**不适用于远程工作区**（远端不支持 worktree）。
- **验证智能体是只读的**，它不能顺手修掉自己发现的问题。
- **只支持 API 交互的 Agent 需要开启工具使用信任**才能担任角色。
- **无进展检测可被「假变化」绕过**：如果每轮都产生无意义但不同的代码变更，检测不会触发。
- 应用完全退出后，运行中的 Loop 不会继续；重启后会对中断的运行做对账。
