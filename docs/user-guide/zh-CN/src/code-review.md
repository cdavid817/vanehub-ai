# 代码评审：审 Agent 改出来的东西

**状态：已实现——桌面端读写真实 Git 工作区；Web/mock 为确定性模拟，回退操作明确标注「已完成模拟回退，未修改本地文件」。**

## 功能概述

Agent 改完一批文件之后，你需要一个地方逐行看差异、标出问题、把意见送回去。会话工作区的**变更**页签就是这个地方，也可以用 [`/changes`](slash-commands.md) 打开。

它和普通 diff 查看器的区别在两点：**评论锚定在内容指纹上而不是行号上**，所以 Agent 再改一轮评论不会错位；**回退是受守卫的破坏性操作**，工作区一旦对不上就直接拒绝。

## 打开评审

在有变更的会话里打开变更页签，系统会**新建或恢复**一个评审会话，并列出改动文件（`审查文件（N）`）。

评审会话**持久化在 SQLite 里**：评论、发现、决定都会跨重启保留。重启后恢复时，系统会先**重新校验工作区凭证**，再呈现当前的锚点位置——不会拿旧快照的行号糊弄你。

## 看差异

- 支持**统一视图与分栏视图**，带行号
- 上一个变更文件／下一个变更文件快速跳转
- 文件列表可折叠，窄屏下也能用
- **复制差异**

差异加载是**有预算上限**的，这决定了几种你会遇到的状态：

| 情况 | 表现 |
| --- | --- |
| 二进制文件 | 标记为二进制，不返回内容 |
| 单文件超预算 | 标记为过大，不返回文本差异 |
| 整体差异超预算 | 保留变更文件清单，改为逐个文件按需加载 |
| 触及安全上限 | 「差异达到安全上限，仅显示部分内容。」 |

**这些不是加载失败**。上限的存在是为了避免一次性把整个仓库读进内存，改动文件的清单始终完整。

被可靠识别的重命名、新增、删除以及有界的未跟踪文本改动都会保留。

## 评论

选中行范围点**添加评论**。评论保存的不只是行号：

**锚点由代码块指纹和上下文指纹共同确定，绝不单靠绝对行号**。所以当 Agent 之后又动了同一个文件：

- 能在有界的同文件上下文里**唯一定位**时，锚点自动迁移到新位置
- 定位不到或有歧义时，评论**标记为过期**，而不是悄悄指向一段无关的代码

点**解决**会把评论转为已解决状态，**保留而不是删除**——审阅历史不会因为你处理完一条意见就消失。

## 决定与「接受」

评审在两个层级上记录决定：整个评审和单个代码块，取值为待定、已接受、已请求修改。

**接受代码块只记录一个决定，不会动 Git 暂存区，也不会改工作区文件**。这是最容易误解的一点：它表达的是「我认可这段改动」，不是「把这段改动应用上去」——改动本来就已经在工作区里了。

## 回退（破坏性操作）

**回退文件**和**回退代码块**会真的修改你的工作区，因此有一整套守卫：

1. **必须显式确认**——「确定回退所选变更吗？此操作会修改工作区。」
2. **路径必须落在本会话的规范工作区内**，遍历、绝对路径、符号链接逃逸在读取或修改之前就被拒绝
3. **文件与工作树凭证必须与快照一致**
4. **原子应用、失败即回滚、不做模糊匹配**

第 3 条的效果是：**快照之后有外部编辑改动了文件，回退会以「过期」为由被拒绝，且不修改任何文件**。宁可不做也不做错——模糊匹配在这种场景下会把改动打到错误的位置。

回退单个代码块时，**同文件中的其他改动保持不变**。

在 Web/mock 里回退只改内存中的 fixture，回执明确写着「已完成模拟回退，未修改本地文件」，**界面不会声称发生了真实的 Git 写入**。

## 把意见送回 Agent

勾选**在反馈中包含评论**，点**发送反馈**。

意见以**结构化信封**通过既有的会话／Agent 边界送达，保留文件、侧、行、代码块、决定和过期标记。原会话收到的是一条有编号、有界的评审反馈消息。

**选中的评论里有过期锚点时，必须显式确认**——「部分所选评论已过期。是否使用过期标记发送？」系统不会把过期锚点的旧行号当作当前内容呈现给 Agent。

## 自动评审动作

页签提供三个白名单动作：

| 动作 | 用途 |
| --- | --- |
| **审查 Agent** | 让 Agent 评审这批改动 |
| **测试** | 跑测试 |
| **安全检查** | 安全扫描 |

它们的终端结果会被归一化成**有界的评审发现**，带严重级别、标题、来源、可选锚点、操作引用和状态。

**动作产不出合法结果时，操作会以页面内可见的输出失败，绝不编造发现**。这条很重要：一个「没有发现问题」的空结果和一个「跑失败了」的结果，含义完全不同。

## 日志里有什么

评审动作只发出**脱敏的元数据事件**：安全 id、计数、操作 id、结果分类、耗时。

**代码、完整差异、评论与发现的正文、提示词、密钥、原始工具输出一律不进诊断日志**。所以日志能告诉你「某次回退因凭证过期被拒绝」，但不会包含被回退的那段代码。

## 注意事项与限制

- **接受不改文件**，它只是一个决定记录。
- **回退会改文件**，且工作区一旦与快照不一致就整体拒绝，不做部分应用。
- **过期评论不会自动消失**，它们保留下来并被标记，发送时需要你确认。
- **二进制与超大文件不提供文本差异**，只给元数据标记。
- **Web/mock 的一切写入都是模拟的**，回执会明说；参见 [Runtime 与功能状态标签](runtime-labels.md)。
- 自动动作依赖既有的 Agent／工具／操作运行时，失败会显式暴露而不是静默返回空。
