# 管理 Skill

**状态：已交付——桌面端与 Web/mock 界面。** 桌面端会执行本地持久化、CLI Skill 挂载和 API Agent 提示词绑定；Web/mock 只模拟相同界面和状态变化，不会修改本机文件或运行时配置。

## 理解列表与状态

“是否启用”和“分配给哪个 Agent”是两个相互独立的维度。

| 界面或状态 | 含义 |
| --- | --- |
| 全部 Skill | 当前管理上下文中每个 canonical Skill id 的一条有效记录，无论它是否启用、是否已分配 |
| 未分配 | 没有分配给任何 CLI Agent 或 API Agent 的 Skill；启用状态不影响这一判断 |
| Agent 页面 | 管理所选 Agent 的“已分配”和“可分配”Skill |
| 已启用 | Skill 级总开关，允许已经分配该 Skill 的 Agent 使用它 |
| 已分配 | 该 Skill 与一个具体 Agent 的关系；每个 Agent 的分配相互独立 |

“已启用”不等于“已分配给所有 CLI”。启用一个尚未分配的 Skill 不会让任何 Agent 自动使用它，也不会让它离开“未分配”列表。

关闭 Skill 会让所有已分配 Agent 暂停使用它，但不会删除这些分配关系。重新启用后，只有原来已经分配的 Agent 恢复使用；未分配的 Agent 不受影响。

## 理解有效定义

Global 与 Workspace 是管理作用域，用于隔离启用状态、分配关系、漂移状态和删除意图。运行时内容来自唯一的有效层，优先级依次为 Project、User、Registry、System。同一 canonical id 的低优先级定义会在“运行时详情”中显示为被遮蔽定义，不会成为独立的活动 Skill。

每一行会标明 Role 或 Utility 类型、eager 或 on-demand 加载方式、有效层、来源、版本、可用性、使用摘要和兼容状态。未显式声明类型或加载方式的已有 Skill 会按 eager Role 保持兼容。

System 包是只读的。你可以预览、启用、停用和分配，但不能直接编辑或删除其内容。Overlay 可以在不改写基础包的前提下定制有效内容；它不会改变基础包的层级或可变性。Utility 委托、捆绑脚本执行和远程包安装在当前运行时版本中未开放。

对于 native API Agent，on-demand Role Skill 可以通过固定的只读 Skill 工具发现和加载。资源引用使用受限的 `skill://` 标识符，而不是本机文件系统路径。Utility Skill 仍会显示，但在委托执行实现前保持不可用。

## 使用 Overlay 定制 Skill

在 Skill 详情中打开“Overlay”，可以比较基础内容与最终有效内容，并查看作用域、信任状态、版本、冲突、资源遮蔽和历史。Overlay 是基础包之上的定制记录，不是另一条活动 Skill。

Overlay 作用域与 Skill 内容层是两套概念：System、User、Project Overlay 依次回放，而基础包仍按 Project、User、Registry、System 选择唯一有效定义。Project Overlay 只属于当前规范化工作区；没有活动工作区时不会加载。高优先级 Overlay 资源可以按相同逻辑路径遮蔽低优先级资源，但不会删除原文件。

常用操作如下：

1. 选择“精确补丁”“学习指导”或“支撑文件”。支撑文件只能位于 `references`、`templates` 或 `assets`，不能是脚本或可执行文件。
2. 先运行预览，检查匹配数量、扫描结果、完整差异和版本见证。
3. 确认后提交。如果基础包或 Overlay 版本已变化，窗口会保留输入并要求重新加载、重新预览。
4. 使用“停用”临时排除一条变更，或使用“回退”创建一个撤销它的新版本。历史记录不会被删除。

本地创建且通过验证的 Overlay 可以立即参与回放。导入包首先进入“不受信任”隔离状态，不会影响 Agent；只有审查指定版本、内容哈希、扫描结果和差异后才能提升信任。检测到私钥、凭据、提示词权限覆盖、脚本标记或伪装的可执行内容时，系统会直接拒绝，不提供强制信任选项。

如果基础包发生变化，Overlay 会显示“需要协调”。在用户确认新的完整差异前，Agent 使用最后一个健康的低作用域结果或基础内容；发生冲突的作用域不会部分生效，依赖它的高作用域也会被阻止。可以编辑冲突变更，或忽略并停用该变更。

钉住 Skill 会保留钉住前已经生效的健康 Overlay，但所有新增、导入、提升信任、停用、回退和协调操作都会变为只读。需要先明确取消钉住才能修改。

默认限制包括：单个支撑文件 1 MiB、导入包 8 MiB、解压后 32 MiB、最多 512 个归档项和 256 条变更；资源路径最多 240 个字符、8 层，历史按 4 MiB 分段。桌面端通过可恢复事务一起提交清单、资源、历史和计数；中断后只会恢复到完整旧版本或完整新版本。不要手工编辑 Overlay 存储或历史文件。

## 典型结果

| 配置 | 结果 |
| --- | --- |
| Skill A 已启用，但未分配 | 没有 Agent 使用它，并继续显示在“未分配”中 |
| Skill B 已启用，只分配给 Codex | Codex 可以使用，其他 Agent 不可以 |
| Skill C 已关闭，已分配给 Codex 和 Claude | 两个 Agent 都暂停使用，但分配关系保留 |
| 重新启用 Skill C | Codex 和 Claude 恢复使用，其他 Agent 不会自动获得它 |

## 启用并分配 Skill

1. 打开“设置”中的“Skill”。
2. 在“全部 Skill”中找到目标 Skill，并确认“已启用”处于开启状态。
3. 在左侧选择一个 CLI Agent 或 API Agent。
4. 在“可分配”面板找到该 Skill，然后选择“分配”。
5. 确认该 Skill 移到所选 Agent 的“已分配”面板。

如果多个 Agent 都需要使用同一个 Skill，请逐个进入对应 Agent 页面完成分配。关闭“全部 Skill”中的“已启用”会暂停所有这些 Agent；它不是单个 Agent 的开关。

## Runtime 差异

- **桌面端：** 为 CLI Agent 分配 Skill 可能会在其 Skill 挂载目录执行文件系统操作；API Agent 分配会保存提示词绑定。操作失败时，错误会留在对应 Skill 行，分配状态不会提前变化。
- **Web/mock：** 可以验证筛选、分配、移除和响应式界面，但所有结果都是内存模拟，不能作为本机文件或 native 配置已经改变的证据。
