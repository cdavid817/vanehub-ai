# 故障排查

按症状找。大部分问题不是 bug，而是某个前提没满足。

以下条目除非注明，都默认你在桌面端。

## CLI 相关

### CLI 显示「未安装」，但我明明装了

VaneHub AI 解析的是**桌面应用能看到的 PATH**，不一定等于你终端里的 PATH——尤其是通过图标启动而非终端启动时。

1. 在普通终端里运行该命令（`claude` / `codex` / `gemini` / `opencode`），确认能跑
2. 能跑说明是 PATH 问题：修正桌面应用可见的 PATH，然后**重启 VaneHub AI**
3. 跑不通说明是安装问题：见[安装并认证 CLI](getting-started.md)

### 显示「已安装但不可运行」

**别重装**。界面的提示就是答案：

> 当前生效的 CLI 已安装但无法运行。请检查 Node、PATH 或该工具自身环境；重装同一版本通常不能直接解决。

文件在，是环境跑不起来——通常是 Node 版本或该 CLI 自身的依赖。

### 显示「安装冲突」

同一个 CLI 装了多份。点**诊断安装冲突**看**安装诊断**，它会列出所有本地安装路径并标出**当前生效**的那个。

**只升级当前生效的那一份**。升级错了，命令行仍然命中旧的，看起来像升级没生效。

如果当前生效的那份来自 VaneHub 只检测的来源——Homebrew、Bun、Volta、桌面应用自带或系统包——就用那个来源更新，CLI 管理页面会告诉你是哪一个。用 npm 再装一份只会让冲突更严重，这也是 VaneHub 不会替你这么做的原因。

### 升级了但版本没变

见上一条。多半是升级作用在了非生效的那份上。

### Agent 要求登录

在对应的 CLI 里完成认证。**VaneHub AI 不保存 Provider 凭据**，也走不了各家的登录流程。认证完回来刷新检测。

OnePiece 是例外——它的 API Key 由 VaneHub AI 保存，见[原生 API Agent](native-agent.md)。

## 会话相关

### 创建会话报「Agent 不可用」

CLI 没装好或没认证。回上面的 CLI 相关条目。

### 创建会话报「Git worktree 创建失败」

worktree 只对 Git 项目可用。选目录时界面会标 **Git** 或**文件夹**——标「文件夹」的会禁用 worktree 选项。

如果已经标了 Git 仍然失败，检查同名 worktree 或分支（`vanehub/名称`）是否已存在。

### 应用崩溃后重开，会话状态不对

应用非正常退出（崩溃、强制结束、断电）后重启时，系统会对中断的会话做一次对账。

**判定只依据持久化的业务证据**——会话、消息、操作和工具记录。**不会**拿时间戳、显示顺序、诊断日志或可观测性记录来推断结论。所以即使统一日志缺失、过期或被你关掉了，恢复也不会因此编造证据。

对账有三种结果：

| 恢复状态 | 什么情况 | 结果 |
| --- | --- | --- |
| **干净** | 能确定地关联到一条已完成或已失败的回复 | 会话回到空闲或失败 |
| **需要处理** | 有判不出效果的工具活动，或证据互相冲突 | **等你确认** |
| **隔离** | 证据结构性无效 | 挂起等人工介入 |

只有未完成的回复、且没有任何工具活动时，**已经落盘的部分内容会被保留**，回复标记为中断或失败，会话回到终态。

### 会话停在「需要处理」怎么办

这个状态的意思是：**有一个外部副作用无法确定到底发生了没有**。比如一条写文件的工具调用中断在半路，从持久记录里看不出它写成功了没有。

**系统不会替你猜**。你可以对当前的恢复版本执行确认，效果是：

- 记录你的确认，解除恢复门禁
- **保留全部证据和中断时的生命周期状态**
- **不重试原来的那次生成**
- **不暗示那个不确定的副作用发生了或没发生**

如果在你确认期间会话又变了，提交的版本对不上会被拒绝，并返回当前状态让你重新审阅——这是防止你基于过期信息做判断。

**中断的工作永远不会被自动重放**。provider 的续跑元数据会保留下来，但系统不会自动恢复或重发那次生成。要继续只能由你发起。

恢复本身是幂等的：重复启动、并发状态变化都不会产生重复报告，也不会把已经终结的状态回退。

> 恢复报告只记录关联关系、决定、安全原因码和有界的证据引用，**不包含提示词、消息正文、工具载荷、命令、凭据或原始 provider 错误**。

### 标签页显示「工作区请求无效或超出当前会话允许的范围」

请求的路径越出了会话工作区边界。VaneHub AI 对工作区外的路径有硬性拦截，这不是可以配置放开的。

另两条相近的提示：**「找不到请求的会话资源」**（资源已被删除或移动）、**「当前运行环境不支持此工作区操作」**（该操作需要桌面端）。

### 标签页只显示了一部分数据

> 第一版采用有界加载，当前可能仅显示部分结果。

这是设计约束，不是丢数据。终端输出另有独立的容量与保留策略。

### 终端输出中间少了一段

输出捕获用的是有界队列，写满时会插入缺口标记而不是阻塞进程。超出保留期或容量上限的记录会被清理。需要长期留存请依赖统一日志，见[可观测性与日志](observability.md)。

## 多 Agent 相关

### 某个席位始终拿不到发言权

**先检查句柄**。句柄由专家角色名派生：空白会变成 `-`，角色重名会自动加后缀。

**围栏代码块内的 `@` 会被有意忽略**——贴一段带 `@` 的代码不会误触发交接。

如果是因为触及提及数量上限或交接链深度上限而停止，会话里会显示具体原因。

### 提到了某个 Agent，但流程没停下来

**只有交接（handoff）会打断流程**，单纯提及是轻量的。这是有意的设计：如果每次提到都要停下来等，Agent 会学会干脆不提，反而让你失去可见性。见[多 Agent 群聊与 `@` 交接](multi-agent-workflow.md)。

## 记忆与个性化

### Agent 没有记忆

**大概率是没配 OnePiece 的 provider。**

CLI Agent 的记忆提取由 OnePiece 代做——没配就不产生任何记忆。**即使你主力用 Claude Code，也要先配好 OnePiece**。见[个性化配置](personalization.md)。

### 想让某个 Agent 有独立记忆

**可以，按每条记忆设置。** 每条记忆都有作用域（全局或某一个工作区）和受众（默认全部 Agent，也可以只给你指定的那几个），不满足条件的记忆不会被注入到那个 Agent 的提示词里。设置入口见[个性化配置](personalization.md#每条记忆的作用域来源与受众)。

注意这条边界只覆盖**注入**。记忆存储仍是一台机器上的共享池，`recall` 工具按设计搜索整个池，不按受众或工作区过滤。所以「受限受众」的含义是**不会被自动带进那个 Agent 的上下文**，而不是那个 Agent 检索不到。真正不希望被任何 Agent 读到的内容，应当删除而不是限制受众。

## 远程与自动化

### 远程工作区用不了 Loop

**Loop 需要独立的 Git worktree，而远端不支持 worktree**。这是能力边界，不是配置问题。

### 远程工作区打不开本地编辑器

> 暂不支持使用本地程序打开远程工作区。

### IM 连接器开不起来

**必须先保存默认路由配置**。界面的提示是「启用任意连接器前必须完成此配置」。见[IM 连接器](im-connectors.md)。

### 定时任务在应用关闭期间没跑

调度器在应用内运行，不是系统级服务。**关闭期间不跑，但重启后会补上错过的运行——且只补最近一次。**

关了三天、每天一次的任务，重启后只补跑一次。见[定时任务与通知](scheduled-tasks.md)。

## 可观测性

### 用链路 id 搜不到日志

**日志条目在来源提供时会把 `runId`、`traceId`、`spanId` 写进它的 context**,所以按标识符关联是可行的。搜不到通常是因为那条记录来自一个没有标识符可带的来源,而不是标识符被剥掉了。

日志刻意排除的是**内容**而非标识符:原始提示词、Agent 输出、源码、诊断文本、stderr、环境变量、凭据与私有绝对路径都不会进入日志文件。如果你搜的是一段输出内容而不是 id,那就是它不在的原因——这种情况用**时间**去对。

### 链路里有些节点展不开

那是**不可见**保真度——外部 CLI 的内部行为属于黑盒。系统只保留边界节点，不会虚构子节点。想要完整可展开的调用链，用 OnePiece。

## 查看日志文件

排查时除了界面里的**日志**标签（见[可观测性](observability.md)），还能直接看落盘的日志文件。

### 日志在哪

日志默认写在应用数据目录的 `logs/` 子目录下，主日志文件名固定为 `vanehub.log`，按天滚动，归档放在 `logs/archive/`，默认保留 30 天。各平台默认路径（应用标识 `ai.vanehub.app`）：

| 平台 | 默认日志目录 |
| --- | --- |
| Windows | `%APPDATA%\ai.vanehub.app\logs` |
| macOS | `~/Library/Application Support/ai.vanehub.app/logs` |
| Linux | `~/.local/share/ai.vanehub.app/logs` |

### 改日志目录

**设置 → 基础配置**里可改「日志目录」（也可改「数据目录」）。改完重启后按新目录重建。

### 日志内容与脱敏

日志分四级：**错误 / 警告 / 信息 / 调试**。落盘前会脱敏——provider 密钥、Bearer 令牌、私有路径、命令参数等敏感信息会被替换为脱敏标记。因此有些排查场景里日志信息不足，可临时在**设置 → 执行可观测性**把采集策略切到「脱敏内容」。采集策略、保留天数等细节见[可观测性](observability.md)。

> **日志与链路是两套存储,但可以按标识符关联**:日志刻意不含原始载荷(提示词、Agent 输出、源码、stderr、凭据、私有绝对路径),但来源提供时会把 `runId`、`traceId`、`spanId` 写进条目的 context。

## 开发相关

### 本地截图和仓库里的不一致

文档截图以固定的 CI 浏览器环境为准。**仅在有意审核 UI 变更时**运行：

```bash
npm run docs:screenshots:update
```

### 启动报 `no such table`

多个 worktree 共用同一个数据库时，跨分支的迁移版本号可能撞车。见[《开发者指南》](../../../developer-guide/zh-CN/src/index.md)的开发环境搭建一章。
