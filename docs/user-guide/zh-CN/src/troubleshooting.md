# 故障排查

按症状找。大部分问题不是 bug，而是某个前提没满足。

## 先确认你在哪个 runtime

**这是最容易误判的一类**。如果你在浏览器里打开 VaneHub AI，那么：CLI 不会被检测、进程不会启动、设置不会保存、文件不会改动——**即使界面提示成功**。

判断方法和完整的能力差异表见 [Runtime 与功能状态标签](runtime-labels.md)。

以下条目除非注明，都默认你在桌面端。

## CLI 相关

### CLI 显示「未安装」，但我明明装了

VaneHub AI 解析的是**桌面应用能看到的 PATH**，不一定等于你终端里的 PATH——尤其是通过图标启动而非终端启动时。

1. 在普通终端里运行该命令（`claude` / `codex` / `gemini` / `opencode`），确认能跑
2. 能跑说明是 PATH 问题：修正桌面应用可见的 PATH，然后**重启 VaneHub AI**
3. 跑不通说明是安装问题：见[安装并认证 CLI](getting-started.md)

### 显示「已安装但不可运行」

**别重装**。界面的提示就是答案：

> 当前生效的 CLI 已安装但无法运行。请检查 Node、PATH 或该工具自身环境；重装同一版本通常不能直接解决。

文件在，是环境跑不起来——通常是 Node 版本或该 CLI 自身的依赖。

### 显示「安装冲突」

同一个 CLI 装了多份。点**诊断安装冲突**看**安装诊断**，它会列出所有本地安装路径并标出**当前生效**的那个。

**只升级当前生效的那一份**。升级错了，命令行仍然命中旧的，看起来像升级没生效。

如果当前生效的那份不是 npm 装的，就用它原本的来源更新——用 npm 再装一份只会让冲突更严重。

### 升级了但版本没变

见上一条。多半是升级作用在了非生效的那份上。

### Agent 要求登录

在对应的 CLI 里完成认证。**VaneHub AI 不保存 Provider 凭据**，也走不了各家的登录流程。认证完回来刷新检测。

OnePiece 是例外——它的 API Key 由 VaneHub AI 保存，见[原生 API Agent](native-agent.md)。

## 会话相关

### 创建会话报「Agent 不可用」

CLI 没装好或没认证。回上面的 CLI 相关条目。

### 创建会话报「Git worktree 创建失败」

worktree 只对 Git 项目可用。选目录时界面会标 **Git** 或**文件夹**——标「文件夹」的会禁用 worktree 选项。

如果已经标了 Git 仍然失败，检查同名 worktree 或分支（`vanehub/名称`）是否已存在。

### 标签页显示「工作区请求无效或超出当前会话允许的范围」

请求的路径越出了会话工作区边界。VaneHub AI 对工作区外的路径有硬性拦截，这不是可以配置放开的。

另两条相近的提示：**「找不到请求的会话资源」**（资源已被删除或移动）、**「当前运行环境不支持此工作区操作」**（该操作需要桌面端）。

### 标签页只显示了一部分数据

> 第一版采用有界加载，当前可能仅显示部分结果。

这是设计约束，不是丢数据。终端输出另有独立的容量与保留策略。

### 终端输出中间少了一段

输出捕获用的是有界队列，写满时会插入缺口标记而不是阻塞进程。超出保留期或容量上限的记录会被清理。需要长期留存请依赖统一日志，见[可观测性与日志](observability.md)。

## 多 Agent 相关

### 某个席位始终拿不到发言权

**先检查句柄**。句柄由专家角色名派生：空白会变成 `-`，角色重名会自动加后缀。

**围栏代码块内的 `@` 会被有意忽略**——贴一段带 `@` 的代码不会误触发交接。

如果是因为触及提及数量上限或交接链深度上限而停止，会话里会显示具体原因。

### 提到了某个 Agent，但流程没停下来

**只有交接（handoff）会打断流程**，单纯提及是轻量的。这是有意的设计：如果每次提到都要停下来等，Agent 会学会干脆不提，反而让你失去可见性。见[多 Agent 群聊与 `@` 交接](multi-agent-workflow.md)。

## 记忆与个性化

### Agent 没有记忆

**大概率是没配 OnePiece 的 provider。**

CLI Agent 的记忆提取由 OnePiece 代做——没配就不产生任何记忆。**即使你主力用 Claude Code，也要先配好 OnePiece**。见[个性化配置](personalization.md)。

### 想让某个 Agent 有独立记忆

做不到。当前记忆是主机级共享池，一个 Agent 记下的内容其他 Agent 也能用。要隔离只能整体关闭记忆。

## 远程与自动化

### 远程工作区用不了 Loop

**Loop 需要独立的 Git worktree，而远端不支持 worktree**。这是能力边界，不是配置问题。

### 远程工作区打不开本地编辑器

> 暂不支持使用本地程序打开远程工作区。

### IM 连接器开不起来

**必须先保存默认路由配置**。界面的提示是「启用任意连接器前必须完成此配置」。见[远程执行与 IM 接入](remote-and-im.md)。

### 定时任务在应用关闭期间没跑

调度器在应用内运行，不是系统级服务。**关闭期间不跑，但重启后会补上错过的运行——且只补最近一次。**

关了三天、每天一次的任务，重启后只补跑一次。见[定时任务与用量统计](automation.md)。

## 可观测性

### 用链路 id 搜不到日志

**日志中刻意不包含任何执行标识符**，这是隐私设计。两者要用**时间**对上。

### 链路里有些节点展不开

那是**不可见**保真度——外部 CLI 的内部行为属于黑盒。系统只保留边界节点，不会虚构子节点。想要完整可展开的调用链，用 OnePiece。

## 开发相关

### 本地截图和仓库里的不一致

文档截图以固定的 CI 浏览器环境为准。**仅在有意审核 UI 变更时**运行：

```bash
npm run docs:screenshots:update
```

### 启动报 `no such table`

多个 worktree 共用同一个数据库时，跨分支的迁移版本号可能撞车。见[《架构与实现》](../../zh/index.html)的开发环境搭建一章。
