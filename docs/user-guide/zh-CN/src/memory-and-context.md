# 记忆与上下文：跨会话记住什么、上下文满了怎么办

## 功能概述

两件相关但不同的事：

- **记忆**解决「换个会话又要从头讲一遍」——把值得跨会话带走的事实存下来，之后自动带入。
- **上下文压缩**解决「聊太长顶到模型上限」——把较早的轮次压缩掉，让对话继续。

## 记忆

### 一个共享池，不按 Agent 隔离

**OnePiece 和全部 CLI Agent 共用同一份记忆**：`claude-code`、`codex-cli`、`gemini-cli`、`opencode`、`antigravity-cli` 都读同一个池子。

在 Claude Code 会话里记下的事实，下次开 Codex CLI 会话照样能用。

系统会记录每条记忆由**哪个 agent、在哪个工作区**产生，但**这只是溯源信息，不作为读取过滤条件**。换句话说，产生它的 agent 和目录不会限制谁能读到它。没有工作区目录时也照样保存，不会因此拒绝。

### 记忆是文件，不是数据库行

每条记忆是宿主级记忆目录下的**一个 Markdown 文件**，frontmatter 里有 `name`、一行 `description`（用来在不读正文的情况下判断相关性）和 `type`，正文就是记忆内容。

**这个设计的意义在于可寻址**：模型能改正或撤回**某一条**，而不是只能不断追加。每条记忆按目录相对路径寻址，两条记忆不会共用同一个路径。

**某个文件的 frontmatter 缺失或解析不了时，系统跳过它继续枚举**，不会让生成、注入或管理界面整个失败。

### 四种类型

| 类型 | 用途 |
| --- | --- |
| **用户** | 你是谁、偏好 |
| **反馈** | 你给过的工作方式指正 |
| **项目** | 进行中的工作与约束 |
| **参考** | 外部资源指针 |

类型缺失或不在这四种之内时**降级为无类型**，仍然可以被枚举、注入和管理——迁移过来的文件和手写的文件都不会因此失效。

### 两个开关

在**设置 → AI 个性化 → 记忆**里：

**启用记忆**——关掉之后，**已保存的记忆也停止被使用**，不只是停止保存。这一点容易误解：它不是「只读模式」，是整体关闭。

**从工具辅助的会话中记忆**——只管一件事：OnePiece 在**用过 shell、文件或 MCP 工具的会话**里要不要自动提取记忆。

这个开关有两个不受影响的范围：

- **你主动要求记住的内容不受影响**，无论开关状态
- **CLI Agent 的记忆提取不受这个开关影响**，它只管 OnePiece

### 管理已有记忆

列表显示每条记忆的类型、来源（自动提取／主动要求记住）和作用范围（某个项目或所有项目）。

| 操作 | 影响 |
| --- | --- |
| **删除** | 删除单条，**不可撤销**，同时吊销它的检索索引 |
| **重置全部** | 删除全部记忆，**OnePiece 和全部 CLI Agent 共享这一份**，不可撤销 |

「重置全部」的确认文案会明确提示这是共享的——因为它清掉的不只是当前 agent 的记忆。

### 注入时带年龄和警示

记忆注入到系统提示词时，**附带的是人类可读的经过时长，而不是原始时间戳**。原因很实际：一个裸时间戳不足以让模型意识到内容可能过期。

超过陈旧阈值的记忆**额外带一段警示**：记忆是时间点的观察，其中关于代码或文件位置的说法可能已经过时，断言为事实之前需要核实当前状态。

**未超过阈值的记忆不带这段警示**——给新鲜内容加警示只是噪音。

### 记忆走独立的上下文预算

记忆召回与代码证据**分开排序、分开配额**，各自占用自己那一份版本化的来源配额，不会互相挤占。

**记忆正文不会出现在选择诊断和持久化的清单元数据里**。

## 自动上下文压缩

### 开关与生效范围

在 OnePiece 设置里打开**自动上下文压缩**：当前模型接近上下文上限时，允许压缩较早的上下文。

**更改只对后续生成生效，正在运行的生成保留它启动时的设置**。所以你在一次长生成进行中改这个开关，那一次不会受影响。

### 什么时候触发

优先级很明确：

1. **有已核实的模型容量和 Token 测量时，以 Token 口径为准**
2. **证据不足或分析失败时，回退到固定字符数阈值**

关键在于系统**不会凭空编造容量或 Token 值**。两种回退情形：当前模型没有已核实的上下文窗口元数据、或者这次请求快照测不出 Token。

有一个反直觉的结果：**Token 证据显示占用未达阈值时，即使字符阈值已经越过也不会压缩**。Token 口径可用时它就是权威判据，字符数只是它不可用时的兜底。

### 压缩发生时你会看到

**对话里会插入一条可见的通知**，明确说明较早的轮次被压缩了。它走的是和其他富文本块相同的持久化与渲染路径，不会刷新一次就没。

### 什么情况下会跳过压缩

即使满足触发条件，下列机制也会抑制自动压缩：

| 机制 | 作用 |
| --- | --- |
| **请求级抑制** | 本次请求跳过 |
| **生成级冷却** | 刚压过一次，短期内不再压 |
| **失败熔断** | 连续失败后停止自动尝试 |
| **用户偏好** | 你关掉了开关 |

这些抑制会留下**不含内容的证据记录**，可以在上下文健康里看到，但记录里没有任何提示词或工具内容。

## 上下文策略健康

这一页看的是**不含原文的压缩结果与测量覆盖率**：

| 指标 | 含义 |
| --- | --- |
| **已评估决策** | 评估过的上下文决策数 |
| **结果分布** | 各种结果的占比 |
| **路径分布** | 走了哪些决策路径 |
| **策略版本** | 生效的策略版本 |
| **测量质量** | 测量本身的可信度 |
| **节省字符** / **测得节省 Token** | 压缩省下多少 |
| **Token 覆盖率** | 有多少比例能测到 Token |

**这三件事它都不代表**，界面上也明写了：

- **不是计费记录**
- **不是提供商的缓存指标**
- **不证明回答的语义质量**

它衡量的是运行质量估算，不是账单，也不是「答得好不好」。

保留策略同样明确：**只保留获准的计数、枚举、版本、时间戳与关联标识，提示词和工具内容不会进入历史**。

## 注意事项与限制

- **记忆是全 Agent 共享的**，删除和重置会影响所有 agent，不存在「只清 OnePiece 的记忆」。
- **关闭「启用记忆」会同时停止使用已有记忆**，不是只停止新增。
- **「从工具辅助的会话中记忆」不管 CLI Agent**，也不管你主动要求记住的内容。
- **删除记忆不可撤销**，且会一并吊销检索索引。
- **压缩开关的更改不影响正在运行的生成**。
- **Token 口径可用时压过字符阈值**，字符数只是兜底。
- **上下文健康的数字不是计费数据**，用量计费请看 [定时与用量](automation.md)。
