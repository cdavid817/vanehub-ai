# 个性化

## 功能概述

把「关于你的信息」「风格偏好」「项目里积累的知识」统一存起来，在 Agent 执行前自动注入，省去每开一个会话都要重新交代一遍。

所有内容都在**设置 → AI 个性化**一个页面里管理，不再分散在各处。页面分四个视图：

| 视图 | 看什么 |
| --- | --- |
| **总览** | 每个已注册的 Agent 最终拿到什么，以及其中每一部分来自哪一层 |
| **指令** | 选一层来编辑自定义指令，并看到它与下层如何合并 |
| **记忆** | 已保存的记忆、待审查的建议、新建、重置与存储健康 |
| **运行预览** | 在某个 Agent、某个工作区、某个会话模式下，这一次实际会用到什么 |

**专家角色**（Expert Role）仍在**设置 → 专家角色**里管理：它描述的是一份工作，不是关于你的信息。

## 作用域：四层，从下往上覆盖

同一份指令可以写在不同的层上，越靠上的层优先级越高：

| 层 | 适用范围 | 优先级 |
| --- | --- | --- |
| **全局** | 所有 Agent、所有工作区 | 最低 |
| **单个 Agent** | 指定 Agent，不限工作区 | ↑ |
| **单个工作区** | 指定工作区下的所有 Agent | ↑ |
| **工作区内的单个 Agent** | 指定工作区里的指定 Agent | 最高 |

**工作区层优先于「单个 Agent」层**，因为项目约定通常应该压过个人对某个 Agent 的偏好；确实需要例外时，写在最上面那层。

每层自己决定**怎么和下层合并**：

| 合并方式 | 结果 |
| --- | --- |
| **继承下一层** | 本层不写内容，完全用下层的 |
| **追加到下一层之后** | 下层内容保留，本层接在后面 |
| **替换下一层** | 只用本层的，下层内容不再注入 |
| **本层不应用任何指令** | 这一层往下的指令全部不注入 |

编辑时页面下方的**从下层继承**面板会写明「保存后会对下方各层做什么」，不用先保存再去猜。

> 编辑后需要点**保存**才会写入，离开输入框不会自动保存；**放弃修改**把文本恢复成已保存的样子。
>
> 如果你打开编辑器之后、保存之前，这一层被别处改过（另一个窗口、另一台机器同步过来），保存会被拒绝并弹出对照：左边是你的文字，右边是当前存储的文字，由你选择保留哪一份。**不会有一方被静默覆盖**。

## Agent 覆盖范围

**总览**视图逐个列出当前注册的每一个 Agent，以及它实际拿到了什么：指令是否生效、生效来源是哪一层、能否读取记忆、能否自动抽取记忆。

这里不存在写死的 Agent 名单——新增一个 Agent 之后它会自己出现在表里。某个 Agent 不支持某项能力时，那一格显示**该 Agent 不支持**，而不是显示成「关闭」；两者的区别是后者你可以打开，前者不能。

记忆的传递方式分三档，也在这张表里：**不传递记忆**、**仅索引**、**索引加选中正文**。

## 自定义指令

在**设置 → AI 个性化 → 指令**里填写两段内容：

| 字段 | 写什么 | 上限 |
| --- | --- | --- |
| **关于你** | 身份、背景、长期偏好 | 3000 字符 |
| **回复风格** | 输出格式、语言、详略程度 | 3000 字符 |

例如在**回复风格**里写「始终用中文回答，结论先行」，在**关于你**里写「我是一名后端工程师，主要使用 Rust 和 TypeScript」。

## Agent 记忆

Agent 在会话中发现的项目约定会被记下，下次开新会话直接可用。

两个开关：

| 开关 | 作用 |
| --- | --- |
| **启用记忆** | 总开关。**关闭后也会停止使用已保存的记忆**，不只是停止新增 |
| **从工具辅助的会话中记忆** | 控制 OnePiece 在用过 shell、文件或 MCP 工具的会话中是否自动提取。你主动要求记住的内容不受影响 |

> **第二个开关不影响 CLI Agent**。界面上的说明写得很明确：Claude Code、Codex CLI、Gemini CLI、OpenCode、Antigravity CLI 的记忆提取不受这个开关影响。

### 每条记忆的作用域、来源与受众

已保存的记忆列表按页显示，只列名称和元信息；正文要打开某一条才读取。可以按这些条件筛选：

- **作用域**：这条记忆属于全局，还是只属于某一个工作区
- **由谁记录**：`你主动要求的`、`OnePiece 抽取的`、`某个 CLI Agent 抽取的`、`模型工具提议的`、`从旧版本迁移而来`、`在 VaneHub 之外编辑过`
- **谁可读取**：默认是全部 Agent；也可以限定成只有列出的那几个能读到，列表里会标为**受限受众**

**「由谁记录」和「谁可读取」是两件事**：某个 Agent 记下的内容可以只给另一个 Agent 读，也可以谁都不给。这也是过去「记忆只能整体开关、无法按 Agent 隔离」这一限制的解法。

在记忆详情里还能把一条标为**已标记为敏感**、**归档**（不再注入但保留）或**删除**（文件一并移除，不可恢复）。

### 待审查：自动抽取只产生建议

自动抽取**不会直接写入活动记忆**，它产生的是待审查的建议，在**待审查**区列出。在你做出决定之前，这里的内容一条都没有存入。

每条建议可以：**批准**、**先修改再批准**、**合并到已有记忆**、**标为敏感并归档**，或**拒绝**。批准时还可以选择保持建议的作用域与受众，或者改成你想要的。

你自己在**新建记忆**里写的那条不走这个队列——作者是你本人，直接进入活动记忆。你也可以在会话里对某条消息直接选择「记住这个」。

### 记忆什么时候被抽取

抽取依附于**上下文压缩**——对话变长触发压缩时顺带进行。这是尽力而为的，不保证每条有价值的信息都被记下。

**CLI Agent 的记忆抽取由 OnePiece 代做**。这是界面上看不出来、但会实际影响你的约束：

> **未配置 OnePiece 的 provider 时，Claude Code、Codex CLI、Gemini CLI、OpenCode、Antigravity CLI 都不会产生记忆抽取。**

原因是这些 CLI 没有可复用的模型凭据，抽取动作需要借助 OnePiece 的 provider 完成。**所以：即使你主力用 Claude Code，只要想要记忆功能，就得先配好 OnePiece**。配置方法见[原生 API Agent](native-agent.md)。

## 会话模式：单个会话可以用多少个性化

新建会话时可以在工作区旁边选一个模式，这个选择在会话创建时定下，之后不再随设置变动：

| 模式 | 含义 |
| --- | --- |
| **标准** | 使用自定义指令，以及这个 Agent 能读到的全部记忆 |
| **仅本项目** | 只使用当前工作区的记忆；新记忆需要审查 |
| **临时** | 不使用记忆，本次会话的内容也不会被记住。指令仍然生效 |

**仅本项目**需要先选定一个项目才能选；没有项目时它是禁用的，并写明原因。

选了**仅本项目**或**临时**的会话，在会话顶部会一直挂着一个提示标记，把当前的取舍写在那里——不是一闪而过的提示，因为这个事实在整个会话期间都成立。

## 重置与修复

### 重置记忆

**记忆**视图里的**重置记忆**先给出计数再执行：匹配到多少条、其中多少条是全局的、多少条属于工作区、会一并删除多少条待审建议和多少个不可读文件。**删除的就是计数所说的那些，所选作用域之外的一概不动**。

确认需要手动输入确认短语。执行后会逐个存储面报告结果（文件、索引行、检索条目、隔离条目）；**如果某个面没能清理干净，页面会直接说出来**——因为在修复之前，那条记忆仍可能被召回。

### 存储健康与重建

**存储健康状况**面板显示存储当前的状态：`就绪`、`迁移中`、`正在重建派生视图`、`另一个进程正占用存储`、`需要修复`、`失败`。

**重建派生视图**用文件重新生成索引与检索条目，并把读不出来的文件移入隔离，不会改动文件本身。面板会记录上次重建的时间。

从旧版本升级时，原有的记忆会被完整迁移过来；个别损坏的条目会进隔离而不是被丢弃。迁移没有完成之前，读取一律返回空而不是返回一半——半份数据比没有数据更危险。

## 运行预览

**运行预览**回答一个具体问题：选定某个 Agent、某个工作区、某个会话模式之后，这一次实际会用到什么。

它列出**会生效的指令**、**被排除的，以及原因**，以及记忆里有多少条被判定可用。**它不显示核心提示词、记忆正文和文件路径**——这些要么不属于你能改的部分，要么应该在记忆详情里读。

## 注意事项与限制

- **仅桌面端可用**，记忆与设置都依赖本地存储。
- **不会改写各 CLI 自己的配置文件**——不会去动 `CLAUDE.md`、`AGENTS.md` 之类，也不接管这些 CLI 自己的记忆文件。
- **不接管各 CLI 的内部上下文压缩**。Claude Code、Codex CLI、Gemini CLI、OpenCode、Antigravity CLI 在自己进程里怎么压缩上下文，VaneHub 不参与也不改变；这里管的是 VaneHub 注入什么，不是它们内部怎么裁剪。
- **OnePiece 自带的核心指令不可编辑**，自定义需求请通过自定义指令或专家角色表达。
- 个性化配置读不出来时**按最保守的方式退让**：生成照常进行，但不注入自定义指令、也不使用长期记忆。一次瞬时错误不会让你得到一个「读不到配置就当全部放行」的会话。
