# 核心概念

理解这几个术语，后面的章节会好读很多。**每个术语首次出现时给出英文原文。**

## 会话（Session）

**会话是 VaneHub AI 的核心工作单元**。一个会话绑定一个工作区目录和一个或多个 Agent，承载对话、终端、文件变更与执行追踪。

会话有五种生命周期状态：

| 状态 | 含义 |
| --- | --- |
| `idle` | 空闲，可以提交任务 |
| `starting` | 正在启动 |
| `running` | Agent 正在产出 |
| `failed` | 执行出错 |
| `stopped` | 已停止 |

处于 `starting` 或 `running` 时界面会禁用重复提交。

会话可以**分类**、**置顶**、**归档**。归档后会话仍可查看与导出，但**不能激活、发消息或启动生成**。

## Agent

**Agent 是执行任务的主体**。VaneHub AI 内置 5 个：

| Agent | 提供方 | 形态 |
| --- | --- | --- |
| Claude Code | Anthropic | 外部 CLI |
| OpenCode | OpenCode | 外部 CLI |
| Codex CLI | OpenAI | 外部 CLI |
| Gemini CLI | Google | 外部 CLI |
| Antigravity CLI | Google | 外部 CLI |
| OnePiece | VaneHub | **原生 API Agent** |

前五个是**外部 CLI**——VaneHub AI 启动它们的进程并管理进程之外的部分（启动参数、权限拦截、输出采集），真正的代码生成由 CLI 自己完成。

**OnePiece** 不同：它直接通过 HTTP 调用模型 provider，完全在应用内运行，详见[原生 API Agent](native-agent.md)。

## 席位（Seat）与专家角色（Expert Role）

**席位是「一个 Agent + 一个专家角色」的组合**。一个会话可以有多个席位，它们共享同一条对话线索，通过 `@` 交接发言权。

**专家角色**定义这个席位的职责、指令、可绑定的 Skill，以及能否担任评审。角色名会派生出被 `@` 时使用的**句柄**。

详见[多 Agent 群聊与 `@` 交接](multi-agent-workflow.md)。

## 工作区（Workspace）

**工作区决定 Agent 能看到哪些文件、命令在哪里执行**。三种形态：

| 形态 | 说明 |
| --- | --- |
| 本地项目目录 | 最常用 |
| Git worktree | 为同一仓库的不同分支建独立工作区 |
| 远端路径 | 通过 SSH 连接的远程主机目录 |

创建会话时若项目是 **Git 项目**，可勾选**创建新 Git worktree**；普通文件夹则会禁用该选项。

> **远端工作区不支持 worktree**——只能指向远端已存在的路径。

## 权限模板（Policy Template）

**权限系统是 Agent 危险操作的统一闸门**。四档模板决定 Agent 能自己做什么、什么需要问你：

| 模板 | 执行命令 / 写文件 |
| --- | --- |
| 只读 | 拒绝 |
| 标准 | 每次询问 |
| 信任 | 放行 |
| Yolo | 放行 |

**读文件与写记忆在所有档位下都放行**——即使「只读」也允许读取，那正是这个名字的含义。

详见[权限审批](permissions.md)。

## Loop（循环工程）

**Loop 是目标驱动的自动循环**。你给出目标与必过检查，它反复「执行 → 验证 → 判定」直到达成或触顶，**并且永远需要你人工验收**。

详见 [Loop 工程化](loop-engineering.md)。

## MCP 服务器（MCP Server）

**MCP（Model Context Protocol）服务器为 Agent 提供额外工具**。在 VaneHub AI 里集中注册一次，就能按 Agent 下发，不必在每个 CLI 里各配一遍。

详见[工具与扩展](tooling.md)。

## Skill

**Skill 是可复用的能力包**。分**全局**与**工作区**两种作用域，可绑定到指定 Agent。Skill 是文件系统上的实体，可能被绕过界面修改，因此系统会做**漂移检测**。

详见[管理 Skill](skill-management.md)。

## 执行追踪与 Span

**一次任务从提交到结束的全过程会被记录成一棵 Span 树**，分四层：会话 → Agent → 工具/MCP 边界 → 进程执行。

每个节点带**保真度**标注，说明这段记录的可信程度：

| 保真度 | 含义 |
| --- | --- |
| 原生 | 运行时的一手记录 |
| 中继 | 经中继层观测 |
| 推断 | 由其他信号推断 |
| **不可见** | **只知道边界，内部不可见** |

外部 CLI 内部发生了什么是黑盒，因此只保留边界节点，**不会虚构子节点**。详见[可观测性与日志](observability.md)。

## Web/mock 预览

**同一套界面也能在浏览器里跑**，用确定性的模拟数据。它适合看界面，但**不会启动进程、不写数据库、不碰文件系统**。

任何标注**仅 Web/mock** 的操作都不构成本机真实发生的证据。见 [Runtime 与功能状态标签](runtime-labels.md)。
