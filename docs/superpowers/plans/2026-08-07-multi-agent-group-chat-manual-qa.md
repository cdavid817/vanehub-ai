**预期**：内置角色只提供「复制」，没有编辑和删除。复制后得到一个可编辑的副本，名字会区别于原件。

## 四、交接（核心，必须用桌面客户端 + codex-cli）

回到第 2.7 步创建的那个会话（架构师 + 实现者，都是 codex-cli）。

### 4.1 第一条消息走谁

1. 在输入框发：`帮我给登录接口加上限流。`（**不带任何 `@`**）

**预期**：消息交给**第一个席位（架构师）**处理。顶部出现轮次状态条：`架构师 正在处理  交接 1/15`。

结果：

### 4.2 Agent 之间的自动交接

接着 4.1 等它回复完。

**预期（关键）**：
- 架构师给出方案后，在**行首**单独一行写出 `@实现者`
- 系统**自动**发起实现者的这一轮，无需你做任何操作
- 状态条变成 `实现者 正在处理  交接 2/15`
- 实现者的消息带**它自己的角色头像和颜色**（🔧 绿色），标签是 `实现者 · Codex CLI`

**如果架构师没有输出行首 `@`**：请记录它的完整原文。这是 design.md 里明确标为「跨厂商不确定」的风险点，属于有价值的负面结果，不是你操作错了。

结果：

### 4.3 句中的 `@` 不触发

1. 发一条：`@实现者 你先别动，我想问下 @代码审查 会怎么看这个方案。`

**预期**：只路由给**实现者**（行首那个）。句子中间的 `@代码审查` 当作普通文字，**不触发**任何交接。

结果：

### 4.4 代码块里的 `@` 不触发

1. 发一条：

````
帮我把交接规则写成文档示例，用代码块包起来：
```
@实现者 这样写
```
````

**预期**：代码块里的 `@实现者` **被忽略**，不触发交接。

> Agent 解释交接规则时一定会贴例子，那不能真的把人叫过来。

结果：

### 4.5 不能 @ 自己

1. 想办法让某个席位在回复里 `@` 它自己（比如直接要求：`请在回复末尾行首写 @架构师`）

**预期**：自我提及被过滤，**不会**触发它自己的第二轮。

结果：

### 4.6 单条最多 @ 两个

1. 会话里凑够三个及以上席位（用 3.3 的方式加）
2. 让某个席位一次 `@` 三个人（每个占一行行首）

**预期**：只路由**前两个**，并且界面上**说明链条为什么截断了**，不是悄悄少一个。

结果：

### 4.7 席位串行、不并发

观察 4.2 和 4.6 的过程。

**预期**：多个席位被路由时，它们**一个接一个**说话，不是同时开跑。后说话的那个能看到前面所有人的回复。

> 并发的话，后面的席位读到的线程会缺掉前一个人的回复——而那恰恰是它被交接过来要处理的东西。

结果：

### 4.8 链深上限

如果你有耐心（或者能构造出互相 @ 的场景）：让两个席位反复互相交接。

**预期**：到第 15 轮停下，并明确告诉你**为什么**停了，不是没人回话了。

## 五、交给人（三种意图）

### 5.1 `fyi` 不打断

1. 发：`请在回复行首写一行 @用户 fyi 我已经开始了，然后继续把方案写完。`

**预期**：
- 出现该消息
- **不弹任何阻塞提示**
- 输入框**不被禁用**
- 工作**继续往下走**
- 状态条**不**显示「等待你」

> 只要一个「通知人」的动作会阻塞，Agent 就会学会不通知，人反而失去可见性。这就是分出三种意图的全部原因。

结果：

### 5.2 `handoff` 会暂停

1. 发：`请在回复行首写一行 @用户 handoff 需要你定一下限流阈值。`

**预期**：
- 轮次转给你，状态条显示 `XXX 把球交给了你`
- 后面**不再有任何席位被调用**
- 状态条显示 `已等待 N 分钟`
- **等一分钟以上再看**：这个数字应当**自己往上走**，不需要你刷新

结果：

### 5.3 `handoff` 之后队列被丢弃

1. 构造一条同时包含 `@用户 handoff` 和 `@某席位` 的回复

**预期**：**该席位不会被调用**。等待的席位是在「这一轮会继续」的前提下被路由的，前提没了，队列就该丢。

结果：

### 5.4 `done` 结束本轮

1. 发：`请在回复行首写一行 @用户 done 本轮完成。`

**预期**：状态条显示 `本轮由 XXX 完成`，**不**显示等待时长（本轮结束了，不是在等你），后续没有席位被调用。

结果：

### 5.5 裸 `@用户` 按 fyi 处理

1. 发：`请在回复行首写一行 @用户 我改完了，不要写意图词。`

**预期**：按**告知**处理——不阻塞、不禁用输入框。

> 默认成阻塞会让 Agent 因为提到人而被惩罚，它就会学着不提。

结果：

## 八、已知的边界（不用测，但请知道）

这些是当前实现里明确没做到的，遇到不算 bug：

1. **多席位会话不用 resume，每轮都注入上下文。** `runtime_session_id` 是会话级单值，而每个席位是独立 CLI 进程；resume 席位自己的 provider session 只会重放它自己说过的话，恰好漏掉队友新说的。代价是 token 消耗比理论最优高。

2. **链深 15、单条 2 个 `@` 是照抄 clowder-ai 的常量**，写死在 `seat_turn.rs` 顶部，没有配置入口，也没有实测依据。

3. **没有心跳和僵尸回收。** 某个席位的进程卡死，这一轮会一直停在那里（30 分钟后超时释放）。参考实现有一套八状态托管机，但那是它从实际故障里挣出来的复杂度，这里没有对应的故障记录就不做。

4. **不做并行扇出。** 一条回复 `@` 两个人，是串行两轮，不是并发两轮。

5. **claude-code 和 gemini-cli 的 `@` 行为未验证**（见 0.2）。
